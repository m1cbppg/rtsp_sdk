> **已停止（2026-09-21）**：Profile 作为通用小垃圾召回通道未通过 oracle 可行性实验，因此本在线 Selector 方案不进入生产实施。其状态机和原子切换设计只保留为历史资料。见[正式决策](../decisions/2026-09-21-ground-litter-profile-prior-no-go.md)和[下一路线](2026-09-21-ground-litter-small-detector-roadmap.md)。

日期：2026-09-20。修订：r3（同步离线回放来源契约；在线算法沿用 r2）。状态：算法、运行契约与实施步骤；已补齐设计复核 F1～F4，尚未实现或完成服务器性能验证。

配套方案：[七天 PS 自动生成 N 个 Profile](2026-09-20-profile-factory-v1.md)。资产格式以方案一 §2 为准；本文件定义双方共用的匹配算法、时序选择、运行时提交和事件衔接。两份文件取代旧综合草案的实施要求。历史问题与修订对应见[设计复核记录](2026-09-20-profile-bank-design-review.md)。

离线输入现支持用户提供的回放文件接口，按方案一 §4.4～§4.8 即取、处理、释放 PS；该接口仅服务建库/回放评估。实时 Selector 只加载已经发布的本地 Bank 资产，不在识别 tick 中请求回放地址、下载历史 PS 或等待离线工厂。

工厂与实时流同机运行时仍会竞争网络、CPU/GPU 和磁盘，须按方案一设置离线作业资源上限并实测；不因两个进程逻辑分离就声称生产性能完全不受影响。

## 1. 目标与容错

输入当前监控画面和方案一产出的参考库，系统按画面外观自动选出一张适合当前环境的 Profile，随环境变化切换。用户不设置白天/夜间/雨天时间表，不手动挑参考。

允许少量误报/漏检以及历史七天始终存在的物体被背景吸收。首版不重新鉴定每张参考的“绝对清洁性”，不做永驻垃圾识别，不为极低概率歧义设计审批流程。

必须延续现有 V3.3：semantic 独立识别常规垃圾，prior 独立补小目标，两路在事件层融合。没有可用 Profile 时只暂停 prior；不能要求 prior 候选得到垃圾模型认可后才显示，也不能把 prior 有效掩膜套到 semantic 上。

解决主要问题：环境变化后 prior 长期失效；相近参考反复切换；换参考时虚假清走、事件丢失；分析负载导致实时流延迟。切换是旁路中的参考替换，不是重建 RTSP 流。

## 2. 运行链路、状态与边界

~~~text
最新帧 + 新鲜 actor/context + 现有事件
 -> 独立可见性判断、共同拟合保护区域
 -> 全库小向量粗检索
 -> Top-K 快速精排；必要时跨 tick 有界扩展到整个库
 -> 合格判断、迟滞、驻留、恢复计数
 -> 预加载候选；旧参考有效时继续使用
 -> 最新帧上的一次全尺寸 prior 验证/分析
 -> 在分析边界提交完整参考上下文
 -> 同一个 V3.3 memory 消费当帧证据

semantic 按自己的截止时间调度；不等待候选加载/检索完成
视频解码、编码、发布仍由既有主链负责
~~~

决策与提交分开：Selector 只提出使用/切换意图，不能在小图评分通过时直接宣布已经切换。Runtime 完成全尺寸验证后提交。建议数据契约：

~~~text
SelectionDecision:
  bank_id, bank_version, view_id
  selected_profile_id | null       # 最近提交的参考；非空不代表本帧可用
  candidate_profile_id | null
  status: MATCHED | SWITCH_PENDING | UNKNOWN
  phase: STEADY | SEARCHING | PREPARING | VALIDATING
  prior_allowed: bool             # 本帧分析完成、证据新鲜且通过适用性判定
  score_current, score_best, reason
  visible_fraction, valid_fraction, tested_profile_ids, search_cursor
  input_timestamp, profile_generation, alignment_generation
~~~

旧参考有效时可以 SWITCH_PENDING 且 prior_allowed=true；旧参考失效时立即 prior_allowed=false。输出必须保留“选过什么”和“本帧是否可判断”的区别。启动预热是独立门控，不并入 Selector 状态枚举。

每个 pad 拥有独立 Selector、memory、加载意图和代际。bank/view/算法版本固定后才能比较分数；禁止混用不同分析尺寸的参考。

## 3. 共用的单帧匹配器

### 3.1 匹配区域与几何

所有 Profile 来自同一 view、分析尺寸和几何基准。轻微抖动配准到当前画布；明显转动/变焦时拒绝整组参考，不自动跨机位迁移 ROI。

当前人车、运动区域、OSD、已确认和 pending 目标不参与背景评分/颜色拟合。共同保护区域由直播与已有状态生成，对本 tick 所有候选一致；不能让每张参考自行删除自己的高残差位置以提高得分。

使用分块稳健统计限制少数小目标的影响。启动时未知小目标还没有事件框，也不能凭几个异常像素决定全局选图。拟合排除不等于删除检测区域，完整掩膜契约见 §5.1。

锚点太少或只剩一个小角落时暂停选择。min_anchor_fraction 起步 0.35，另要求空间跨度覆盖多个分散区域；由独立片段校准。不能仅靠一块未被遮挡的小区域宣布全图适配。

### 3.2 粗检索与不会饿死的扩展检索

复用方案一 16×9 分块描述子：亮度、色度、明暗分布、边缘/对比度。比较全部 N 个小向量，不按时间标签筛库，不需要 ANN 服务。保留绝对亮度/色度，不能先把所有图归一化成相同明暗。

正常快速路径：取 Top-3，并加入 current，最多四张小图精排；N≤4 时可以全部精排。Top-3 是加速策略，不是永久候选边界。

无合格候选，或者排名靠前的候选全尺寸验证失败时，启动扩展轮次：

1. 建立覆盖所有 Profile ID 的待查队列，粗距离只决定顺序。先过滤冷却项，再补足 K。
2. 每 tick 最多精排四张：优先检查 current 和已发现的 challenger，其余名额检查尚未访问的候选；搜索期间有预算时至少推进一个新候选。
3. 没有 current/challenger 占位时，每 tick 可查三个新候选。保留游标，不能下一帧又只查相同 Top-3。
4. 普通分数抖动、垃圾出现和轻微光照变化不重建游标。bank/view 改变或持续显著的全局外观变化可开启新轮次；已经排队的候选仍须有被检查机会，不能靠频繁重置无限延期。
5. 找到合格 challenger 后，在后续新鲜帧上复查它以累计恢复证据。它失格/验证失败就继续队列，不回到只有原 Top-3 的状态。
6. 一轮全部失败时保持 UNKNOWN；等待冷却到期/新的外观证据后再试。无有效旧参考时默认每个分析 tick 探测，CPU 压力下可配置退避，但必须记录实际探测间隔。

固定环境、资源可用、无 challenger 占位时，N=24、每次三个新候选，最多八个搜索 tick 能检查完整个库；有占位时按实际新增名额计算上界，最低一个新候选/tick。这个上界只是小图检索机会，不包括恢复确认、加载、全尺寸验证与预算跳过，不能宣传为固定秒数内一定恢复。

全尺寸失败候选冷却默认 10s；冷却项不占 Top-K 名额。其他候选优先获得验证机会，到期后失败项可用新帧重试。持续预算不足必须显示 SEARCH_BUDGET_EXHAUSTED/搜索停顿，不能伪装成“库没有适合参考”。

### 3.3 精排：一个公共尺度上的匹配分数

在 640～960 宽画面计算有限颜色补偿与残差。候选参考映射到同一当前画布；颜色拟合仅允许低自由度全局增益/偏移，使用共同保护区域。

对每个可见网格 b、候选 p：

~~~text
r_b(p) = 0.4 × 标准化亮度残差
       + 0.2 × 标准化色度残差
       + 0.4 × 标准化结构残差

S(p) = 0.5 × weighted_Q50(r_b)
     + 0.5 × weighted_Q90(r_b)
     + 0.2 × 补偿成本
     + 1.0 × 缺失网格比例
~~~

权重是首版工程起点，保存在 matcher.json；构建集/第六天校准后冻结。所有标准化尺度来自共同构建集并设下限。不能让噪声大的 Profile 用自己的巨大标准差把残差除小。

亮度残差包含空间低频分布，阴影落点不同会增大残差；结构项使用梯度/边缘的稳健统计。彩色/灰度变化由特征自然体现，无需人工标签。

共同目标网格中候选缺失的部分要计惩罚，不能只算每张图最好的一小块。当前共同遮挡与资产自身覆盖不足分开统计。分数只是背景匹配代价，不是垃圾概率。

### 3.4 合格判断、旧环境闸门与共享接口

候选要同时满足几何可靠、锚点足够、可见地面覆盖足够、匹配分数与补偿幅度处于验证包络、无严重坏帧/大范围失配。current 使用保持门槛，新候选使用更严格的进入门槛，形成迟滞。

包络从参考来源之外的连续块统计。样本足够时用高分位数加有限余量；支持少时使用公共稳健范围或中位数/MAD 回退。不能把阈值放宽到“任何画面都通过”。第六天校准目标是动态覆盖、少切换、小目标不退化，禁止以框越少越好优化。

Bank adapter 必须替换当前单参考的固定环境判断，不能在 Bank 通过后再次被 local_extent>16 等旧门槛全部拦住。补偿算法仍有界，暴露原始拟合需求和实际裁剪后 gains/biases、local-field 分布、饱和比例、几何诊断；过大的原始需求不能被参数裁剪掩盖。

Bank 包络需在全尺寸 prior 上验证，不只在小图上验证。未知环境超出包络时暂停 prior 并换参考，不能取消环境保护来追求覆盖。固定 Profile 的旧模式保持原默认行为。

共享接口：

~~~text
extract_descriptor(frame, common_mask, feature_config)
match_profiles(frame, profiles, common_mask, geometry, matcher_config)
  -> score / enter_eligible / hold_eligible / coverage / diagnostics
analyze_bank_prior(frame, prepared_context, observation_context)
  -> candidates / support / availability / clean_eligibility / diagnostics
~~~

离线/在线使用同一份实现、特征尺度、补偿、掩膜规则与版本。不能各自实现近似算法。

## 4. 什么时候切换

### 4.1 初始参数

全部参数存入冻结的 matcher 配置，可校准；下表不是线上性能承诺。

| 参数 | 起步值 | 含义 |
|---|---:|---|
| top_k / max_small_matches_per_tick | 3 / 4 | 快速路径与精排总预算 |
| switch_improvement_ratio | 0.15 | 有效旧参考换新参考所需优势 |
| switch_min_samples / switch_min_span_seconds | 3 / 4s | 同一 challenger 的新鲜连续观测 |
| min_dwell_seconds | 10s | 从上次提交算起，仅限制有效旧参考的主动切换 |
| recovery_min_samples / recovery_min_span_seconds | 2 / 2s | 没有有效当前参考时的恢复确认 |
| failed_candidate_cooldown_seconds | 10s | 全尺寸验证失败冷却 |
| max_result_age_seconds | 4s | Bank 结果从采集到提交的最大年龄，独立于显示框 hold |
| cache_profiles / loader_inflight | 4 / 1 | 全尺寸上下文缓存数与每 pad 加载并发上限 |

默认每个分析 tick 选择一次；当前 0.5 FPS 约两秒一次。使用真实输入时间，不能通过重复帧/缓存结果凑样本。challenger 改变、失格、坏帧、选择跳过或时间倒退时清空连续计数；过大观察间隔同样重置，起步上限为 max(4s, 2×计划采样周期)。

保留两类时钟：单调采集/完成时间用于排队年龄、加载超时和提交新鲜度；连续的源视频时间用于观测跨度与事件证据，重连/PTS 回退开启新的时间代际。不能直接相减 Unix 时间与 monotonic 时间。离线回放使用显式虚拟时钟复现间隔和给定处理耗时，不把加速回放的墙钟速度当现场恢复速度。新鲜度的 4s 是 Bank 起步配置，不复用现有目标框 maximum_age_seconds 来放宽旧帧提交。

### 4.2 决策规则

~~~text
先检查 current 的当前帧适用性
按快速/扩展策略取得候选评分

if current 仍合格:
    若无其他进入合格候选，或优势不足：
        保持 current；清空 challenger 连续计数
    否则：
        累计同一 challenger 的连续新鲜观测
        三次且跨度至少四秒、旧参考已驻留十秒：
            请求全尺寸验证；成功才提交
        等待期间继续分析合格 current
else:
    立即停用旧 prior 证据；不受十秒驻留限制
    扩展检索并累计同一候选的恢复观测
    两次且跨度至少两秒、上下文已准备好：
        请求全尺寸验证；成功才恢复
    否则保持 UNKNOWN/SWITCH_PENDING，semantic 继续自己的调度
~~~

优势为 (S_current-S_best)/max(S_current, score_floor)，使用共同正的 score_floor。近似平局优先保持 current，不必追求每帧全库数学意义上的最低分。

这里的“合格 current”还包括最近全尺寸失败状态：小图通过不能把已经失败的旧参考重新直接放行。相同 profile_id 在失效间隔后恢复，也走恢复条件与证据重置；不能直接跨间隔累计 prior 命中/清走。

### 4.3 用户实际会经历的时间

| 情形 | 切换时机 | 等待期间 |
|---|---|---|
| 缓慢变化，旧参考仍好 | 新参考持续优于旧参考；满足三次/四秒及十秒驻留，再完成验证 | 旧 prior 继续产出新证据 |
| 开灯/阴影等突变，旧参考失效 | 当帧停用；找到新参考后满足两次/两秒并验证 | prior 暂停，semantic full-scan 继续 |
| 人车遮挡、暂时无足够锚点 | 不把遮挡当新环境；可用证据恢复后重新判断 | 可见区域按局部规则工作；不足时 prior 暂停 |
| 所有参考不合格 | 不强行切到最接近者；继续有界搜索 | UNKNOWN，记录缺口，semantic 独立 |
| 启动新流 | Selector 可并行准备，仍遵守现有一次性启动预热 | 默认现有 15s 预热期间不累计有效事件命中 |

以两秒一帧、暖缓存、候选在首批、预算充足为例：主动切换最早在首次合格 challenger 观察后的约四秒提交，且要满足旧参考的十秒驻留；失效恢复最早约两秒。环境变化落在两个 tick 之间会额外等待下一采样点，扩展检索、冷加载、重试和处理耗时还会延长时间。

Bank 模式由 Selector 统一负责环境稳定计数，不能再叠加旧 normal_stability_samples 门控；切换也不重复 15s 启动预热。旧固定模式不改。报告必须给真实发现→准备→提交时间线，不能只用上表理论下限。

切换后未确认的纯 prior 小目标重新累计。沿用当前四次命中、跨度至少六秒的配置时，新参考上首次有效命中到确认至少约六秒；若该物体已存在于新参考里，prior 可能不再检出，属于背景参考的能力边界，semantic 仍可独立识别。

## 5. 如何验证并原子切换

### 5.1 三种不同含义的掩膜

| 数据 | 来源与作用 | 不允许的做法 |
|---|---|---|
| fit_mask | 稳定锚点、共同可见性，排除 actor/OSD/已知目标及候选无关的短时运动；仅用于背景拟合/评分 | 把拟合排除直接当检测不可用 |
| foreground_support | 在可判断区域中计算补偿后的结构/亮度残差，按冻结阈值产生小目标证据 | 因某处残差高就先删除它 |
| availability_mask | ROI ∩ 离线有效资产 ∩ 配准后有效视野，再扣独立遮挡/坏帧/确证的大范围成像损失 | 把直播高残差、白色小纸片或未获模型认可当作不可见 |

顺序固定：先独立几何/可见性→共同拟合保护→受限补偿→适用性判断→前景证据。未知小目标靠稳健拟合与固定网格权重保护；不能让每个候选根据自己的残差任意改共同 fit_mask。

availability 的原因应可枚举和追溯，例如 ACTOR_OCCLUDED、FRAME_CORRUPT、GEOMETRY_INVALID、LARGE_EXPOSURE_LOSS、PROFILE_ASSET_UNSUPPORTED。禁止新增只有 LIVE_RESIDUAL_TOO_HIGH 含义的逐像素失效规则。

目标尺度内的新增差异默认交给候选几何过滤与事件时序。大范围反光/失真判据须同时具备超出目标尺度的空间范围与独立证据，例如大片纹理丢失、多个分散锚点同时失配或传感器裁剪；单个高亮区域本身不够。起步在边长超过最大 prior 目标边长两倍、面积超过最大目标面积四倍的范围才评估这类“大范围”规则，并在真实片段上校准。不能把小连通域膨胀后凑够面积。

局部噪声只能使用冻结的离线 noise 阈值与上限，不能按直播残差持续抬高；离线不可靠区域损失要纳入完整 ROI 覆盖报告。环境整体不适配时换参考，不是逐个删掉所有不匹配像素后宣布通过。

另设逐事件 clean_eligibility：局部参考实体冲突可能禁止判断清走，但不应因此禁止正向检测目标。support=0 且 availability=true 是“观察到了没有前景”；availability=false/无新观测是“无法判断”，二者不能合并。

### 5.2 准备与提交协议

切换只更新同一 pad 的参考上下文；不重建流、进程、垃圾模型或 V33EventMemory。

1. **提出意图。** 小图选择器发现 challenger 后即可请求预加载，记录 bank/view/profile 与几何代际。意图未提交时 selected 仍是旧参考。
2. **后台准备。** 用有界加载器读取并核验 reference、valid、noise、描述子，生成候选完整上下文。小图常驻；全尺寸 LRU 起步四个，当前与待提交上下文受保护。上下文在使用期间不能被逐文件替换或淘汰。每 pad 最多一个加载作业，全服务还需共享 I/O/CPU 并发上限。
3. **最新帧验证。** 连续确认条件满足且资产就绪后，用当前新鲜帧进行候选唯一一次全尺寸 prior 分析；同一 tick 不再完整分析旧参考。这次分析先形成临时结果，不修改事件 memory。它也必须检查适用包络、局部有效性和原始补偿需求。
4. **边界提交。** 验证成功、输入仍新鲜、意图和 bank/view/geometry 未过期时，在旁路分析的串行状态更新边界一次性替换 reference、valid、noise、变换和 profile_generation。通知 memory 重置跨参考证据，再消费本帧新证据；本帧可作为新代际第一次 prior 命中。
5. **发布。** 只发布包含完整代际和时间戳的结果，result_version 单调增加。旧异步加载/分析结果不得覆盖当前状态；过期验证结果直接丢弃，不提交。

加载的磁盘资产绑定固定 bank/view；动态 warp 在验证时使用当前帧的几何变换。轻微抖动不应导致刚加载的原始资产被反复丢弃、重新读盘；变换或几何代际变化后必须重做相关 warp/验证，不能提交旧 warp。资产、掩膜、阈值图始终使用相同坐标变换，二值 mask 用最近邻采样，连续图按声明的插值规则处理并验小目标。

缓存除张数上限外，还要限制每 pad 与全服务的字节数：按真实 reference、四项阈值、有效图和临时 warp 的 dtype/尺寸估算峰值，禁止只按 PNG 文件大小算内存。当前与候选上下文的最低同时驻留空间不足时报告资源不满足，不在后台偷偷缩小分析尺寸或强行淘汰正在使用的上下文。完整离线统计可留在资产/报告中，在线只加载分析确实需要的数组。

旧参考仍适合时，准备期间继续旧 prior。正式验证占用当 tick 的 prior 名额，成功时不必额外空出一个分析 tick；失败则该 tick 没有 prior 新证据，不能借用上一帧 support，也不补跑第二次重分析拖慢队列。

启动时校验 manifest、版本、尺寸、路径与资源限制，资产散列在加载/激活前校验。不要为了建流前校验而在视频处理线程同步读完整个库。固定不可变资产版本；校验失败的参考不能进入候选池，记录它导致的覆盖损失。

### 5.3 失败、回退与连续性代际

提交前失败：保留旧引用和事件身份，候选进入 10s 冷却；旧参考在下一新鲜帧仍合格就继续，否则保持 UNKNOWN。不会回填失败 tick 的缺失证据。

提交后下一帧新参考失效：立即暂停 prior，把旧参考作为优先恢复候选之一，但仍需当前帧适配与恢复验证，不能直接恢复旧 support/计数。旧参考可能仍在 LRU 中，因此无需重新加载，但“缓存里存在”不等于“现在适用”。

从 UNKNOWN 恢复到相同 profile_id 时也递增证据连续性代际（可统一使用 profile_generation），执行与换 ID 相同的 prior 窗口重置。普通连续 MATCHED tick 不递增代际。

I/O、资产损坏、单个 prior 分析异常应在旁路隔离为 degraded。若整个推理进程/GPU 故障，semantic 也可能受到影响，需现有进程恢复机制；不能把分支隔离写成对任意故障均“不影响实时流”的承诺。

## 6. 事件、清走与画框如何衔接

### 6.1 坐标固定

同一 Bank 内使用共同几何基准，运行时参考 warp 到当前 live analysis 画布，semantic/actor 框进入同一画布。仅切换参考不改变事件坐标、zone 归属或 ID。

几何变换更新时迁移锚点或使旧 prior 暂不可判断，不能只变参考不变目标坐标。明显机位移动停止该 view 的 prior；跨 view 事件迁移不在首版范围。

### 6.2 哪些状态保留、哪些重置

| 状态 | 普通切换/同参考失效后恢复 |
|---|---|
| V33EventMemory 对象、确认事件 ID/锚点/历史来源 | 保留，不重建 |
| semantic 独立扫描时钟、有效命中窗口 | 保留；其证据仍按自己的新鲜度规则使用 |
| 待确认 prior 命中、跨源快速确认窗口 | 清空，防止跨两张参考凑确认 |
| 旧 prior support 缓存与运行中的 last-prior-seen 新鲜标记 | 失效或绑定旧代际；历史日志保留，不能让旧参考继续贡献 current_support |
| prior/fused 的清走累计及其 last-clean 时间 | 清空，新代际重新获得连续有效证据 |
| 启动预热计时 | 不重启 |
| 当前显示框 | 根据新鲜来源证据与既有显示规则决定，不单靠“有旧 ID”维持 |

已有 prior 事件在新参考上仍有正向支持时关联回原 ID；如果暂时无有效 prior，保留身份但按既有不可判断规则隐藏纯 prior 框。semantic 持续支持的框继续遵循 semantic 的显示规则。切换不能保证纯 prior 框始终可见，不能用无限 hold 掩盖暂停。

### 6.3 防止换参考变成“垃圾已清走”

清走需新参考上的连续、新鲜、局部可见且无 actor 遮挡的证据。普通 profile 切换本身不构成清走证据。

若旧/新参考在已有事件锚点出现超出补偿解释的局部结构/实体冲突，则该事件 clean_eligibility=false；其他区域继续判断。冲突判断使用补偿后的局部结构，不把正常整体亮度变化一律当实体冲突。

最小保守恢复规则：在新参考下重新观测到该事件的正向存在，随后才允许该代际的消失证据累计。否则保持该事件不可判断，按已有 prior_suspend_expire_seconds（当前默认 120s）到期关闭为 unavailable；不能改名 cleaned。此处不要求认证两张参考中哪个物体是垃圾，不增加逐物体人工审批。

暂停超时和清走可用性必须按事件锚点判断，整图 prior_available=true 不能覆盖局部无效。semantic-only 事件沿用自身缺失规则；有 prior 历史的事件不能在局部无效时绕过保护，直接按模型没检出就清走。

上述不可判断计时不能因持续切换而一再归零：事件从最后一次可靠可判断证据开始的暂停时长保留，直到真正恢复局部证据。普通短切换应保留 ID；长期到期后再发现允许新 ID。

## 7. 是否影响实时识别与推流

必须区分“连续播放”“垃圾模型调度”“小目标确认”和“已有框显示”。

| 对象 | 设计行为 | 可能出现的实际影响 |
|---|---|---|
| RTSP 主视频 | 不重启解码/编码/发布，不同步等待选图 | 共享 CPU/GPU/内存仍可能造成抖动，须实测 |
| semantic 全 ROI 扫描 | 自己的时钟到期即获调度，不依赖 prior_available | 算力不足仍可能延迟；必须记录调度迟到 |
| prior 引导的 semantic crop | 有 prior 候选且预算允许时运行 | prior 暂停时自然没有该类裁剪，但不能阻塞全 ROI 扫描 |
| prior 小目标 | 旧参考有效时继续；无参考时暂停；提交后重新累计待确认目标 | 失效恢复有检测空档，确认可能延后 |
| 已有纯 prior 框 | 身份保留，是否显示取决于新鲜证据 | 暂停时可能隐藏，不能承诺视觉上零闪断 |
| 有新鲜 semantic 支持的框 | 保留独立证据和身份 | 不应因单纯 Profile 切换被清空 |

每 tick 预算：N 个小向量比较，最多四个小图精排，一次完整 prior；不对 N 张参考运行全尺寸 prior，不给每张参考重复跑模型。沿用每 pad latest-wins 和时间戳拒旧，禁止累计待处理帧。

调度顺序需从现有“先 prior 后模型”显式改为有截止时间的预算调度：先预留/执行到期 semantic full-scan，再执行有界选择与一次 prior，剩余预算处理候选裁剪/预准备。actor/context 只复用满足新鲜度要求的结果；没有可靠遮挡信息时不能把陈旧掩膜当清走证据。不要用“复用”跳过必要的可见性判断。

长时间不执行 crop 或扩展搜索必须有饥饿指标与告警/报告。先降低预准备并发、小图尺寸、非必要重搜频率，必要时按明确配置降低旁路频率，不能静默积压队列。候选全尺寸验证替代旧 prior 的该次分析，不额外插入第二次重任务。

CPU/GPU 原生调用不一定能中途取消，因此耗时预算不是硬实时中断保证。超时后 latest-wins、拒绝过期结果，并收缩下一轮可选工作；不靠复制帧制造稳定 FPS。

起步验收目标：新增匹配/选择 P95 ≤100ms；完整 tick P95 <2000ms、输入帧年龄 P95 <4000ms；主流唯一 FPS ≥20、目标接近源 25，duplicate=0。均待服务器实测。历史 1762.65ms 来自 prior 暂停条件，不能证明 active prior+Selector 满足该预算。若实际处理能力不足，报告吞吐与识别延迟，不得声称“两秒一次”已实现。

必须分别测暖缓存、冷加载、连续成功切换、失败扩展、active prior+semantic、多个 pad。播放顺畅不能替代事件确认时延和 prior 可用性的验证。

## 8. API、配置与可观测性

请求中的 profile_id（固定）和 profile_bank_id（自动）二选一；hybrid 继续要求垃圾模型。以下仅为待实现接口，当前 API 不支持直接调用：

~~~json
{
  "ground_litter": {
    "enabled": true,
    "mode": "hybrid_v33",
    "profile_bank_id": "camera_01_bank_v1",
    "model": "turhancan_yolov8m_seg_trash.pt"
  }
}
~~~

Bank ID 解析到受控根目录中的不可变版本，拒绝任意路径/越界资产。流启动锁定整个 Bank 版本；V1 不在运行中热替换 Bank，仅在库内切换参考。补充 PS 后离线出新版本，按既有发布流程启用。

| 文件/模块 | 变更 |
|---|---|
| ground_litter_profile_bank.py | 两方案共用 schema、校验、资产、有界缓存 |
| ground_litter_profile_match.py | 两方案共用特征、评分、进入/保持判定 |
| ground_litter_profile_selector.py | 纯时序逻辑、扩展游标、冷却、切换意图、提交/失败反馈 |
| ground_litter_profile_analysis.py | Bank adapter、诊断、三个 mask 与逐事件 clean eligibility |
| ground_litter_v32.py | 必要时抽取补偿/残差纯函数与原始诊断，旧默认行为不变 |
| ground_litter_process.py | 每 pad 上下文、调度/加载/提交、移除 Bank 重复稳定门控、异常隔离 |
| ground_litter_v33.py | 切换通知、局部证据与窗口重置、连续性代际 |
| ground_litter_detection.py、api.py、manager/worker | 字段互斥、Options 传递、状态快照、日志 |
| Dockerfile、打包脚本、API 示例 | 新模块/资产版本、候选包及固定模式回滚 |

旧 yolo、固定 clean_reference_v32、固定 profile 的 hybrid_v33 行为保留。新字段贯通 API→Options→manager→worker→process，不能只改请求 schema。

metrics 至少包括：选中/候选 ID、bank/version/generation、状态/原因、排名与实际已查集合、搜索游标、候选冷却、准备/验证/提交耗时、失败次数、局部可用面积、unknown/暂停时长、切换原因和次数、semantic_due_lateness、crop/search 饥饿、selector/prior/整 tick 耗时、输入帧年龄、各来源事件数。

小图 MATCHED 率、静态 potential coverage、实际动态 prior coverage 分开。时间权重按方案一 §7.2，不把掉帧/验证失败/过期结果填成可用；完整 ROI 与可见合格区域两个分母都报告。

## 9. 实施步骤与依赖顺序

先完成设计契约和纯逻辑，再接入旁路，最后测服务器；不先改生产 API 请求来掩盖底层未实现。

| 步骤 | 实施内容 | 可检查的交付物 |
|---|---|---|
| B0 | 与 A0 固定资产/掩膜/代际/时间契约，准备小型样例 Bank | schema、原子上下文、成功/失败观察样例 |
| B1 | 纯 Selector：进入/保持、扩展游标、冷却、恢复、意图/反馈 | 确定性轨迹；第四名可用必被查到；预算不足有原因 |
| B2 | 共享 matcher + Bank adapter，替换新模式固定环境门槛 | 同帧离线/在线一致；小目标不因 residual 被设 invalid；旧模式回归 |
| B3 | 接入加载、唯一全尺寸验证、串行提交与 memory 通知 | 事件身份连续；窗口正确重置；旧代际拒收；相同 ID 恢复也隔离证据 |
| B4 | 截止时间调度、API/Options/manager/worker、metrics 与打包 | 全链 round-trip；无 prior 时 semantic full-scan 正常；多 pad 隔离 |
| B5 | 与 A4/A5 做第六天动态校准、第七天冻结回放 | N/过渡参考贡献、覆盖、暂停、确认延迟、误报样例与切换视频 |
| B6 | 构建隔离候选，按授权执行服务器测试 | active prior 的时延/FPS/帧年龄、冷/暖加载、回滚材料 |

依赖链：A0/B0→A1～A3 与 B1→共享 matcher/adapter（A4 单帧基础/B2）→工厂动态定稿及 B3/B4 集成→B5/B6。B1 用样例分数和资产可提前完成，离线工厂不等待生产上线；工厂冻结 N 必须运行同一个 Selector。

A3 先给背景候选，B2 可用基础阈值样例运行；正式 noise 等共享补偿版本固定后回填/重算，再进行 A4 覆盖评估。B2 不依赖最终 N，A4 不依赖生产部署。

每阶段提交代码、测试/数据版本、失败样例、耗时与已知误差。准备与调度成本在离线模拟中明确标注，服务器未测前不冒充真实在线性能。

B5 通过与工厂相同的 recording source/cache 按时间顺序消费五分钟 PS。文件边界不得重建 Selector/memory；预取延迟单列为离线 I/O 成本，只有源录像本身的缺口进入观测时间线。线上运行不依赖 PS 缓存；删除已处理临时 PS 不影响已发布 Bank 的使用。

## 10. 必测场景和验收

| 场景 | 必须验证 |
|---|---|
| 固定/缓慢变化 | 迟滞与驻留避免来回切；旧参考有效时不中断新证据 |
| 突然开灯、全部失配 | 当帧拒绝旧 prior，不等待十秒；semantic 仍独立 |
| 第 K+1 个才合格 | 扩展游标前进并找到它，不永久 UNKNOWN |
| 前几名高清验证失败 | 冷却后补足候选；不永久重复试失败第一名 |
| 人车经过/白色 8×8 小目标 | 遮挡与前景分开；有/无目标成对检查 fit、valid、support、事件 |
| 小纸片、模型无结果 | prior 可独立确认；不能引入语义许可闸门 |
| 噪声恒定大残差、MAD=0 | 使用残差中心和超 cap 诊断；不靠抬高阈值吞小目标 |
| 确认事件跨参考/同 ID 失效恢复 | ID 保留，pending/fused/clean 窗口不串代；不重复预热 |
| 清走、遮挡、同位置再投 | 真实时间、局部可判断；切换不凭 residual=0 宣告 cleaned |
| 参考含已有物体 | 实体冲突禁止虚假清走；长期不可判断关闭原因 unavailable |
| 四秒 A/B 外观循环 | 静态/动态覆盖分开；过渡参考动态剪枝，不把 100% 潜在覆盖当实时覆盖 |
| 慢加载/坏资产/迟到旧结果/丢帧 | 不重建流、不积压；旧代际不覆盖新状态，不前向填成有效 |
| 多 pad 与满负载 | 不互相清空 memory；实测 semantic 调度迟到及主视频唯一 FPS |
| 七天恒定物体 | 允许吸收为背景，不能因此重新要求清洁标注或零漏检 |

先用合成/固定序列验证逻辑，再用真实连续录像验证适配与算力，结论分开。重点是持续大面积误报、普遍小目标漏检、频繁切换、虚假清走和卡流；少量剩余误差逐例报告，不能改成零误报/100% 覆盖闸门。

B5 至少对照固定下午 Profile 与自动 Bank，按小时/地面分区报告动态覆盖、暂停 P95/最长、切换/准备/提交时延、目标确认时延（包括失败）、分来源事件与审核样例。有限样本不宣称全天准确率。

发布顺序为候选验证→版本冻结→隔离试点→生产启用→保留固定 Profile 回退。运行时单次切换失败遵守 §5.3；整个候选版本回退使用原有模式与资产，二者不能混称。

## 11. 自审结论与交付边界
