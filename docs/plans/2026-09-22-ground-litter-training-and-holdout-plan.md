# 垃圾候选分类器：训练前冻结与独立留出计划

日期：2026-09-22  
状态：执行中；正式训练由用户亲自操作。

## 1. 当前要训练的对象

第一阶段不重训 YOLO 检测器，也不把卡片标签伪装成检测框标注。训练对象是一个
**候选二分类头**：输入仍由 `turhancan_yolov8m_seg_trash.pt` 低阈值产生的候选
crop，再使用冻结视觉特征判断“保留为垃圾候选”还是“过滤为非垃圾”。

原因：现有卡片标签只回答框内目标是不是垃圾，不能校正框的位置；它们足以训练
候选过滤器，但不足以监督 YOLO 的定位头。先训练轻量分类头可以在几分钟内验证
数据是否有用，失败成本远低于直接微调整个检测器。

## 2. 第三批标签如何使用

第三批共 300 张：240 张语义候选、60 张随机网格。语义候选由旧分类器的分歧、
边界和新颖度主动选择，因此适合补充训练难例，不能作为无偏测试集。随机网格用于
审计候选生成是否漏掉明显垃圾，不进入候选二分类器训练。

标签映射：

- `LITTER` -> 正例；
- `NON_LITTER` -> 负例；
- `UNCERTAIN`、`BOX_WRONG` -> 第一阶段排除，不强行变成负例；
- `random_grid` -> 不进入候选分类器训练。

## 3. 冻结独立留出集

从 2026-09-18 尚未向审核者展示的语义候选中抽取 200 张。抽取不得读取
Turhancan 特征分类器或 YOLO26s 特征分类器的分数、margin、通过结果和新颖度。

分层为：5 个摄像头 × 4 个候选排名段 × 2 个候选来源，每层 5 张：

- 排名段：1–10、11–20、21–40、41–60；
- 来源：`semantic_full`、`semantic_tile`。

每层按固定种子和 `proposal_id` 的 SHA-256 稳定排序。发布每层总体数、抽样数和
逆抽样概率权重。这样既能覆盖低分小目标，又能在评估时恢复到候选池总体口径。
留出集 ID 在训练前冻结，训练代码禁止读取其标签。

这 200 张与主动学习训练卡来自同一天候选池，所以它是“未展示候选留出”，不是
跨日最终验收。它用于快速判断训练是否过拟合。跨日最终证据仍来自旧的逐日外推、
逐摄像头外推，以及模型完成后的新日期只读 shadow。

## 4. 训练与评估顺序

1. 冻结第三批 300 张标签、选择元数据、文件哈希和统计报告；
2. 冻结 200 张留出卡并完成人工判断；
3. 将前两批明确语义标签与第三批明确语义标签合并为训练候选；
4. 分别训练 Turhancan 冻结特征头和 YOLO26s 冻结特征头；
5. 阈值只由训练集的逐摄像头 OOF 预测确定，目标召回 90%；
6. 冻结权重、归一化参数和阈值后，才读取 200 张留出标签；
7. 报告分层加权总体指标、未加权压力指标、各摄像头/来源/排名段指标；
8. 选择单头或双头融合时必须使用训练/校准数据，不能依据留出结果反复调规则；
9. 通过后做新日期 shadow，只生成事件和审核卡，不立即进入生产告警。

## 5. 合理闸门

候选分类器的职责是减少误报，不能解决 Turhancan 根本没有提议的垃圾。第一阶段
按以下边界判断：

- 候选留出加权召回 >= 90%；
- 候选留出加权负例减少 >= 30%；
- 有至少 5 个正例的摄像头，召回不低于 80%；
- 新日期 shadow 中不得出现持续同位置高频误报；
- 不确定标签单独报告，不纳入主指标。

样本量较小时，单摄像头指标只作诊断，不因一两个样本直接否决路线。若召回达到
而负例减少不足，则保留分类器作为排序器继续主动学习；若召回也明显不足，再进入
带真实框标注的检测器微调，而不是反复调阈值掩盖问题。
