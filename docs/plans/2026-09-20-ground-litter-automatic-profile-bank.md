## 1. 目标与边界

输入同一摄像头的历史 PS 录像，自动生成 N 个参考 Profile。在线依据当前画面的实际适配程度选择一个 Profile，用于 V3.3 的 prior 分支。N 由覆盖收益与质量约束自动决定，用户无需命名白天、夜间、雨天，也无需逐文件选择参考图。

“最适合”定义为：视角正确、背景可信、能解释当前整体环境、保留局部新增物体、可判断地面范围足够。不能定义为差分最小或输出垃圾框最少。

延续 V3.3 双通道召回契约：semantic 可独立确认瓶子、袋状垃圾等；prior 可独立确认模型漏掉的小垃圾。垃圾模型未检出不能证明参考图干净，也不能否决 prior。Profile Bank 只管理先验适配，不承担垃圾语义分类。

本设计允许少量剩余误报，重点防止错误参考导致漏检、虚假清走和频繁切换。它不承诺仅凭未标注录像自动证明所有地面都没有垃圾。

## 2. 已核实的现状

- `ground_litter_process.py` 的 `_HybridPadState` 持有单一 `profile`、`aligned` 和独立 `V33EventMemory`，尚无 Bank/Selector。
- `ground_litter_v32.py` 的 Profile 资产为参考图、有效区域、二值 `daylight_tolerance.png`；该二值图不是统计噪声标准差图。
- `protected_normalize()` 的 `gain/bias/local_extent` 使用固定门槛，返回诊断主要是状态和饱和比例；新选择器需要完整原始诊断。
- `build_ground_litter_v32_afternoon_profile.py` 使用人工选定参考及比较图，不能直接充当自动背景工厂。
- 2026-09-19 隔离服务器测试中 prior 仍因 `GLOBAL_LIGHT_CHANGE` 暂停；当次普通 tick P95 为 1762.65ms。这不是全天适配或 prior 实时性能已通过的证据。

实施不得只在目录中增加 N 张图而继续绑定固定 `profile_id`；也不得让新 Selector 通过、旧 prior 门槛仍一直拒绝，却将其统计为成功适配。

## 3. 总体结构

```text
PS 文件目录 + 已有机位 ROI
  -> 文件清点、时间解析、质量检查
  -> 稀疏采样 + 主动补采
  -> 视角分组、统一坐标
  -> 自动发现外观状态
  -> 分块背景重建、污染检查、可信范围估计
  -> 独立片段适配评估、覆盖压缩
  -> 冻结 Profile Bank（N 个 Profile + 选择规则 + 证据）

当前帧 + actor/context + 已有事件
  -> 小图粗检索 Top-K
  -> 稳定背景区域精匹配、适用性校验
  -> 时间稳定器
  -> 一个 selected_profile 或 UNKNOWN
  -> 一次全分辨率 prior 分析
  -> V3.3 事件融合；semantic 按原节拍独立工作
```

离线可以使用录像前后文重建未来使用的参考库。回放验收必须保持时间隔离：不能用某段录像清走后的画面构建 Profile，再声称成功在线检测了同一段录像的清走。

## 4. 输入与高效采样

### 4.1 文件层

用户只提供 PS 根目录和摄像头身份；复用已经校准的多边形 ROI。新机位的业务地面范围不能仅凭稳定像素推导，必要时集中确认一次 ROI，不要求用户选 Profile。

清点文件路径、大小、编码、分辨率、实际可读时长、时间来源与置信度、解码错误、作业状态。文件名、导出元信息、画面时钟依次辅助恢复时间；文件修改时间和文件内 PTS 不能直接当录像绝对时间。

SQLite 保存断点；作业键包括输入身份、配置版本、算法版本。源文件只读，文件未变化可复用缓存。生成资产保存来源文件完整 SHA-256、解码时间戳和帧摘要，保证能够回到原片。

纠正此前讨论中的口径：完整 SHA-256 必须读取文件所有字节，不能称为“只读少量元数据”。初扫可先记录 stat 与弱指纹，素材被选作 Profile 来源时计算完整哈希；如需整个原始语料完整校验，再后台顺序读取全部文件一次。弱指纹不得标成完整校验。

### 4.2 抽帧策略

先在代表性 PS 文件实测随机定位成本与时间正确性，再选择 seek 或单次顺序解码。PS 缺少可靠索引时，抽三帧不等于只解码三帧。FFmpeg 的 seek 会涉及前置 seek point 及后续解码，具体成本以文件实测为准。[FFmpeg 官方说明](https://ffmpeg.org/ffmpeg.html#Main-options)

- 初始每文件取约 5s、中点、结束前 5s，以及一个由文件身份固定种子的随机时刻；无有效时长时先恢复时间轴。
- 小图用于检索与质量特征，建议宽 640～960；细小垃圾判别与最终参考重建必须回取原尺寸帧。
- 约 2016 个完整五分钟文件对应约 8064 张初始小图；这是设计采样数，补采量由数据决定。
- 出现覆盖空缺、片内/片间突变、背景歧义、定位异常时，补采到 30s、5s，必要时解码 10～30s 的连续短窗口。
- 稳定区段也保留固定种子的随机审计样本，避免首中尾采样永远看不见中间的短变化。
- 每批补采后重算新增覆盖收益；停止于质量达标或预算用尽。预算用尽仍未解决的区域明确标记未知。

低频输出能减少推理和存储，不保证按同比例减少解码。保存轻量特征与少量证据图，避免全量转 MP4、全量落盘高清帧。

### 4.3 数据隔离

在聚类与背景重建前分组：前五天构建，第六天校准，第七天冻结盲测。相邻切片、重复下载、重叠片段必须归同一集合。第七天可预先清点文件，但其画面特征、聚类和参考图不得参与构建与调参。

前五天内部按日期/不连续时间块交叉验证，不能随机拆相邻帧冒充独立样本。日期无法可信恢复时改用可确认的不重叠时间块，并标明独立性较弱。

## 5. 统一视角与坐标

先按固定视角分组（view epoch）。轻微抖动做受约束配准；明显转动、变焦、裁剪变化单独成组，不能靠任意透视形变强行匹配。

每组冻结一个共同坐标画布、ROI、OSD 排除区和分辨率。所有 Profile 离线对齐到该画布；生产为 1080p 时保留原素材并生成对应 1080p 资产，不能以放大替代原生细节。

在线将同组 Profile 通过共享的、已验证的几何变换映射到当前画布后比较；不能让不同候选各自扭曲到残差最小。彩色/灰度切换可以形成不同外观候选，但仅凭颜色改变不判定机位移动。

配准检查包含分散内点、ROI 内误差、尺度/角度/位移边界和局部一致性。阈值以实际最小目标像素校准：平均全图误差小不代表远处六像素纸片区域也对齐。

## 6. 自动生成可信候选 Profile

### 6.1 发现外观状态

对固定网格提取空间亮度分位数、色度、低频明暗分布、边缘结构、清晰度与饱和区域。保留各块位置，避免同样平均亮度但阴影落点不同的画面被视为等价。

特征优先来自稳定背景与地面周边，剔除 OSD、可识别人车、运动前景和已有疑似物体；分块稳健汇总并限制单块权重。垃圾语义框只是一项污染提示，误报框与漏检不能作为真值。

使用半径约束的代表点聚类：从质量最佳的样本开始，按当前代表集合不能解释的最大残差选新代表；近邻归组，离群样本进入补采队列。代表点和半径用于生成候选，不直接决定最终 N。

不能单凭局部出现一个包裹、桶、纸片就新增环境类。候选之间若仅有局部实体差异，应进入污染/场景结构变化检查；只有可靠的整体外观差异带来新覆盖时才允许新增 Profile。

### 6.2 分块重建背景

对每个外观组主动选取不同日期、不连续时间段中的高清帧，优先选择能补齐未被遮挡地面的素材。起步目标为跨三天、多时间块的观测；不足时降低可信范围或列为 provisional，而非伪造独立支持。

重建流程：

1. 配准后屏蔽人车、运动物、过曝/欠曝、坏帧、已知垃圾及具有投放/移走迹象的局部区域。
2. 对每个重叠图块保留多个实际观测外观模式，包括不同时间段支持、可见次数、切换前后证据。
3. 候选背景模式依据跨时段复现、地面纹理连续性、遮挡解除前后的一致性和邻块一致性排序；每个时间块贡献设上限，避免连续数小时停车压倒短时间露出的地面。
4. 区分“出现频率高”与“确为清洁地面”。两个局部模式无法判定哪一个是垃圾时，不取更常见者硬当清洁背景。
5. 尽量以一张清晰的真实代表帧为底，仅对有充分证据的遮挡区域进行来源可追踪的块替换；块内使用实际观测代表，降低逐像素中位数造成的模糊与拼接伪影。
6. 只允许来自兼容外观组的替换；块边缘检查亮度、纹理和梯度接缝。不能用强光地面直接补入暗处，也不能用生成式补图伪造可检测地面。
7. 留出来源之外的时间块检查重建残差、局部伪影和污染风险。

“综合空间连续性与时间观测重建背景”有背景初始化研究基础；这里的清洁判据、证据账本和参考库选择是面向本项目的工程设计，需要现场验证，不是引用研究后就得到质量保证。[背景初始化研究](https://arxiv.org/abs/1406.5095)

### 6.3 输出资产

每个 Profile 包含：

| 资产 | 用途 |
|---|---|
| `reference.png` | 不可变的高清背景 |
| `valid_mask.png` | 有足够背景观测且可用于检测的地面 |
| `clean_confidence` / `clean_evidence` | 背景可信度等级、支撑时间块及来源；不是已校准概率 |
| `noise_maps` | 清洁可见条件下的亮度/结构残差统计，包含 MAD/分位数与样本数 |
| `selection_descriptor` | 小图快速检索特征 |
| `environment_envelope` | 配准、补偿、残差与可用范围的经验适用区间 |
| `provenance` | 源文件/帧/图块、算法配置、校验值 |

噪声统计只用通过污染检查的留出观测，按不连续时间块平衡计权。对检测阈值可采用有上限的残差分位数加余量；样本不足需回退到保守默认值或未知。

不得用最大历史差异作为容差，也不得把持续垃圾、人流或移动阴影直接转为很高的噪声标准差。容差过大时该区域降为不可靠，并计入覆盖缺口，不能假装可检测。

## 7. 自动确定 N：以有效覆盖压缩候选

对候选 Profile 与独立时间块代表帧建立稀疏适配矩阵。只有同时通过背景可信、配准、环境匹配、有效地面覆盖和小目标保护检查，才记为“覆盖”。每个单元还记录它实际可判断的地面网格。

同一时刻的覆盖只能来自一个被选中的 Profile，不能将 A 的左半边与 B 的右半边合并统计为整帧覆盖。优化时每个时间样本有唯一分配 `a_i ∈ B ∪ {UNKNOWN}`，最终以实际 Selector 的分配重算成绩。

样本权重取所代表的不重叠时间长度，并平衡关键地面分区；主动补采出的十张相邻帧不能比同一时间段的一张代表帧多出十倍权重。远处目标区单独报告，避免近景大面积地面掩盖远景不可用。

目标为带成本的覆盖优化：

```text
选择 Profile 子集 B，使
  J(B) = 未覆盖的时间×地面权重
       + λ × Profile 数量
       + μ × 污染/高容差风险
最小，且每个已选 Profile 均满足质量门槛。
```

这是工程近似优化，不声称贪心解为全局最优。实现用增量覆盖贪心，再做删除冗余和局部替换：

1. 选择带来最多可靠新增覆盖的候选。
2. 补入当前未覆盖外观状态的候选，而非重复覆盖最常见画面。
3. 对低频但持续出现的状态设置独立覆盖约束；不能因夜间/特殊状态占比低而全部舍弃。
4. 新候选只在原有物体区域更像当前帧、却没有新增可靠环境覆盖时拒绝。
5. 删除不会使覆盖或小目标保持能力显著下降的冗余 Profile。
6. 达到覆盖目标、没有合格新增候选或到达资源上限后停止；未覆盖状态单独报告。

候选预检采用描述子近邻与抽样时间块，避免所有高清帧两两比较。最终保留库必须重新运行实际 Selector 与 prior，而不是只凭聚类距离验收。

N 可以是 3、8、15 或其他值，不能提前承诺 4～10。首版可设 `N_max=24` 作为工程资源上限；达到上限但覆盖未达标应报告失败/缺口，不得把上限解释为最优 N。

## 8. 在线选择：粗检索、精匹配、绝对拒绝

### 8.1 两种区域不能混用

- **选择区域**：稳定背景锚点、分散结构和地面周围的低频外观，用于判断整体环境。
- **检测区域**：业务地面 ROI 中可信且当前可见的像素，用于找小垃圾。

新垃圾不能主导选 Profile。已确认事件、pending 候选、近期运动区域、actor/context 和 OSD 从选择/颜色拟合区域排除。尚未检出的极小目标通过分块中位数、低频特征和单块权重上限降低影响；这不等于从检测区域删除它们。

保护掩膜应在候选精排前冻结，并对所有候选一致。禁止每个候选只排除自己最不匹配的区域。掩膜覆盖过多导致锚点不足时转为 UNKNOWN，不能不断扩大掩膜让任意背景通过。

### 8.2 粗检索

每个旁路 tick 在小图上提取描述子，对整个 Bank 排名，取 Top-3 并始终加入当前 Profile。N 较小时直接遍历特征向量，无需向量数据库或新增大模型。

不按时间、天气标签筛选。所有合格 Profile 都有被检索机会；上线后的选择不得依赖人工昼夜表。

### 8.3 精排评分

使用固定空间网格、共同锚点和共同量纲计算：

```text
S(p, frame) = w1 × 稳健低频亮度残差
            + w2 × 空间明暗结构残差
            + w3 × 边缘/纹理不一致
            + w4 × 有限颜色补偿成本
            + w5 × 缺失/低可信网格惩罚
            + w6 × 超出适用分布的惩罚
```

先逐块计算，再用中位数与高分位数汇总。初始权重可等权标准化，标准化尺度来自构建集的固定统计；第六天校准后冻结。候选之间不得各用一个无界噪声尺度除残差，否则最模糊、容差最大的 Profile 会占便宜。

每个候选使用同一目标网格计分，缺少可信像素必须被罚；检查足够共同锚点与每个关键地面区覆盖。不能用只覆盖一小块的 Profile 与覆盖全部地面的 Profile 直接比较平均误差。

颜色补偿仅允许受约束的稳健全局增益/偏移，并计入成本；不允许精排阶段用高自由度局部变形/局部调色抹去物体。彩色和灰度模式的可比较特征及适用区间由素材校准，不人工命名。

### 8.4 排第一不等于合格

返回最低分之前检查：

- 视角/配准通过；
- 锚点数量、空间分布和可信地面覆盖足够；
- 绝对残差、补偿幅度、饱和/黑区及局部异常比例在适用范围内；
- 新 Profile 不含当前事件处的可疑局部实体；
- 与次优候选接近时，两者背景含义是否一致。

前两名分数接近且背景等价时优先保持当前 Profile，不必停用；分数接近但局部背景冲突时，冲突区域不可判断，必要时整路 prior 暂停。所有候选都差时输出 UNKNOWN，不强制挑一个。

### 8.5 Profile 合格与 prior 真正可用同口径

Bank 新建版本化的适配判定：完整记录 gains、biases、local field 分布、空间异常、饱和与配准误差，由独立时间块校准各 Profile 的适用包络，再叠加固定安全边界与目标保护测试。

具体校准起点：在构建集内部逐时间块留出，得到可信背景的各项残差与匹配分数分布；进入门槛取高分位数加有限余量，退出门槛略宽，二者均有固定上限。以第六天的未知时长、切换次数和目标保护失败数选择稳定参数。样本不足时不估计尾部分位数、不自动放宽。没有真实正负标签时，这只是经验适配校准，不能将分位数解释为误报概率或将自动通过画面当作真值。

不把 `local_extent=16` 简单改大；也不让 `MATCHED` 绕过最终分析。冻结的 Bank 校准器与在线 prior adapter 必须使用同一版本判据。旧单 Profile V3.2/V3.3 路径维持原行为，新 Bank 路径显式启用。

最终有效区域是可信背景、业务 ROI、当前可见性和局部适配区域的交集。局部反光/遮挡可使局部未知；全局视角错误、锚点不足则整路 prior 暂停。局部判定需传至事件锚点，不能只用一个全局 bool 判清走。

## 9. 切换与事件保护

状态为 `MATCHED`、`SWITCH_PENDING`、`UNKNOWN`。起步参数：每个分析 tick 评估、连续三次且真实跨度至少四秒的优势后切换、有效旧 Profile 最短驻留十秒。数值仅作第六天校准起点。

规则：

1. 当前 Profile 合格时，新候选需超过切换收益门槛并持续满足，避免相近候选来回切。
2. 当前 Profile 已不合格时立即暂停旧 prior，不能因最短驻留时间继续错判；新候选通过稳定验证后接管。
3. 所有计时基于不同新鲜帧的真实时间；不能把同一缓存结果算成多次稳定命中。
4. 切换不重建 `V33EventMemory`、不重新执行 semantic warmup、不改变事件 ID。
5. prior pending 的确认窗口和清走累计按切换代际重置；已确认事件身份保留。新鲜证据恢复前，沿用 V3.3 的暂停/显示规则，有 semantic 支撑的事件可继续显示。
6. 新 Profile 在事件锚点没有可靠清洁参考时不得给 clean evidence；已有事件不能因为“换图后差分为零”直接清走。
7. 连续未知超过现有 `prior_suspend_expire_seconds` 时仍按 unavailable 到期，绝不能标成已清走；普通切换必须与长期到期分开统计。
8. 旧版本/旧切换代际的分析结果丢弃；结果包含 bank version、profile ID、alignment generation 与输入时间戳。

参考图在在线识别期间保持不可变。新素材可以自动进入离线候选队列，经过相同构建与独立验证生成新版本；不把“长时间没移动”自动写成背景，也不自动原位覆写旧库。

禁止对 N 个 Profile 逐像素取最小残差、逐像素选择最像的背景或将 N 路候选直接合并：任意一个污染背景都可能由此掩盖垃圾。首版每 tick 只使用一个全局 Profile，允许它的局部不可用。

| `scripts/build_ground_litter_profile_bank.py` | PS 目录到候选库与报告 |
| `scripts/evaluate_ground_litter_profile_bank.py` | 时间隔离回放、反事实测试和盲测报告 |

Profile schema 新增独立 kind/version；不能将统计噪声图直接塞入旧二值 tolerance 文件。导出兼容旧资产只能作显式转换，不能据此声称旧 loader 支持新语义。

API 设计为 `profile_id`（固定）与 `profile_bank_id`（自动）二选一。这是待实现配置，当前 API 不支持直接调用。配置须贯穿 API、Options、manager、worker、进程、metrics、样例、Dockerfile 与测试。

`_HybridPadState` 增加 bank/selector，保留原 memory；切换时仅更新 prior 参考和相关缓存。semantic tiles、扫描时间表不能被 Profile 切换重置。状态机增加逐事件位置的 prior 可判断信息，未知点不能由零 support 误判清洁。

日志至少包含选择排名、各项分数、拒绝原因、有效地面比例、切换原因/次数、profile age、观测时间、选择耗时、各来源事件数。禁止以框少、全局 MATCHED 数高替代可用覆盖和漏检验证。

## 11. 算力与吞吐

- 所有 N 个 Profile 只比较小图特征；Top-3 做中等分辨率匹配；全尺寸 prior 每 tick 一次。
- 统一对齐缓存，正常 tick 不重复对 N 张图跑 SIFT。
- Bank 小图常驻；高清参考按有界 LRU 缓存，预加载可能切换的候选。错失缓存时暂时 UNKNOWN，不阻塞主推流。
- 选择器增量耗时起步目标 P95 ≤100ms，必须实测；全分析仍遵守现有 tick P95 <2000ms、帧年龄 P95 <4000ms 等约束。
- 现有 1762.65ms 是 prior 暂停条件下的历史测试，不能据此保证新增选择与真实 prior/crop 一定容纳得下。
- 不足时先优化分辨率、缓存和检索频率，降检索频率期间仍每 tick 监测当前适用性；不得积压帧或降低主链唯一帧率。

离线单机限制解码与模型并发、总缓存与待处理队列。先用 24h 试点测 seek、解码、特征与模型各自耗时，再估算七天成本，不预先声称固定小时数或加速倍数。

## 12. 验收：验证“选对且没吞垃圾”

### 12.1 自动检查

1. **背景来源与污染**：每个有效块能追溯来源；已知垃圾不得进入清洁参考；无法判定区域必须出现在缺口报告。
2. **独立覆盖**：报告完整时间×ROI 面积上的有效覆盖，以及可见地面条件下覆盖；同时逐小时/逐外观组报告，不能把未知夜间从分母去掉。
3. **检索质量**：在冻结盲测样本上离线穷举同库候选，比较 Top-K 是否遗漏合格候选及在线选择代价。穷举最佳仅是选择器参照，不是真实垃圾标签。
4. **目标保护反事实**：在保留画面上加入不同位置/大小/对比度的小物体，测试选图不被物体诱导、残差不被消除、模型无结果时 prior 仍能确认。
5. **污染诱导**：人为构造“与当前垃圾更像但有污染”的参考，检查其不得被发布/选中或在该位置提供清走证据。
6. **切换生命周期**：垃圾出现→环境改变→切换→遮挡→清走→再次投放，保留逐帧证据，确认不重复建事件、不虚假清走。
7. **未覆盖输入**：新视角、大遮挡、黑屏、反光与未知外观正确拒绝；semantic 独立运行。
8. **资源/兼容性**：多 pad 最新帧、旧结果拒收、缓存释放、缺失资产、旧模式行为、主视频链吞吐回归。

合成反事实是防算法“吞目标”的结构测试，不代替真实六像素纸片召回率。清洁背景检测与评价需要可核实真值，不能用算法自己判清洁再证明自己零误报。[背景初始化评价研究](https://arxiv.org/abs/1506.04051)

### 12.2 初始工程目标与证据边界

目标值在看到第七天前冻结，建议作为试点目标而非已经达到的保证：

- 可见、画质合格地面上的时间×面积有效先验覆盖 ≥95%，并逐小时报告最低值；完整业务 ROI 的覆盖另行报告。
- 粗检索对同库合格最优候选的 Top-K 命中 ≥99%；分组样本不足时只列明细，不报有统计意义的百分比。
- 目标保护/切换确定性场景全部通过；真实已标注目标保留原有召回，不得用提高覆盖换漏检。
- 稳定画面无无意义切换、无切换导致的单帧闪框；切换等待时间单列，不混入稳定误报。
- 真实回放报告 prior-only、semantic-only、fused 的持续误报/小时和未知/未审核事件数量；不新增“零误报”前置闸门，不把原有 semantic 误报混成 Profile 失败。
- 若沿用 V3.3 每四小时一个总持续误报的工程目标，必须说明它是全系统目标、目前未证明，不能由 Profile 选择准确率代替。

第七天完整按实际分析节拍回放；解码可以顺序流式处理，仅输出证据片段，无需落盘所有帧。固定种子抽查无事件时段以查漏检，不能只审核算法已产生的框。

盲测失败后该天转为开发数据，再次调参须换独立时间段验证。盲测通过后冻结该库；若用全部七天重建，属于新版本，原盲测成绩不能直接继承，需新增独立录像/未来影子验证。

## 13. 人工参与与不可识别情况

正常工作自动完成文件处理、补采、聚类、选 N、生成参考、阈值校准、在线选择及运行报告。用户无需挑参考帧，也无需填写天气/昼夜标签。

系统生成少量按“影响面积×持续时间×不确定性”排序的复核卡片：只展示歧义地面块的前后对照、来源及可能影响。相同位置合并卡片。可由执行 agent 做初审并标明非人工真值；用户只处理确需业务判断的少数例外。

如果用户完全不参与复核，则歧义区域保持未知、semantic 继续运行。参考库仍可自动产出，但可用覆盖可能较低，真实准确率仍缺少可靠标签。

尤其是某张纸在七天中始终存在、且模型未识别时，像素观测本身可能无法区分它与路面固定纹理。重复出现、低方差、跨天一致都不能逻辑证明它是干净地面；自动污染检测也可能漏掉这种情况。这是输入证据不足，不可通过增加 N 或调高容差解决。

## 14. 分阶段实施与交付

1. **24h 输入试点**：确认 PS 解码/时间/视角、ROI 复用、成本，交付素材质量报告与断点清单。
2. **离线工厂**：构建候选、可信掩膜、来源图和自动覆盖压缩，交付 Bank、N 的选择理由与缺口。
3. **Selector 影子回放**：不接线上，完成穷举对照、校准、目标保护、污染和切换测试。
4. **V3.3 集成候选**：版本化 schema/API、局部可判断信息、切换不重置事件、最新帧/性能回归。
5. **冻结盲测与报告**：全天覆盖、真实样本、误报/遗漏证据、选择延迟、资源和未解决区域；通过后才提出生产试点。

失败定位必须具体：素材缺口、清洁背景歧义、检索漏选、适用性判错、prior 检测失败或 semantic 原有误报分别报告，避免全部归为“需要更多 Profile”。

## 15. 设计自审

| 检查问题 | 本设计处理 |
|---|---|
| 需要用户知道何时白天/雨天吗？ | 不需要；按画面外观检索，时间用于样本独立性与追溯 |
| N 是否自动决定？ | 按可靠新增覆盖选择与剪枝；有资源上限且显式报告缺口 |
| 最高相似度会吸收垃圾吗？ | 清洁重建、统一选择掩膜、局部污染检查、反事实测试共同限制；不宣称绝对保证 |
| 静止物体会被当干净地面吗？ | 不能以静止/多数票证明清洁；留歧义与已知局限 |
| 模型未检出会阻止 prior 吗？ | 不会；semantic 仅是素材污染提示之一 |
| 没有合适 Profile 怎么办？ | 局部或全局 UNKNOWN；semantic 继续；不强行选第一名 |
| 切换会清空事件或误清走吗？ | 共享 memory、统一坐标、切换代际与逐事件清洁可信性 |
| 能一直学新画面吗？ | 离线版本化重建；不在线吸收静止物体 |
| 是否把稀疏抽帧当完整检验？ | 没有；主动补采、随机审计、连续盲测各自承担不同目的 |
| 离线覆盖会比线上能力虚高吗？ | 单时刻只分配一个 Profile，按实际 Selector 重算；补采帧按真实时间计权 |
| 是否已经证明可用？ | 没有；当前交付是设计，质量和预算需实际 PS 及回放证明 |

自审结论：满足“自动生成 N 个 Profile，并在识别时自动选一个”的产品方向；可按上述阶段实现。最大不确定性是现有素材能否提供足够可信清洁地面，而非白天/夜间分类能力。
