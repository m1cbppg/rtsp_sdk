# 垃圾候选上下文分类器短周期筛选方案

日期：2026-09-22  
状态：已停止；ConvNeXt-Tiny 候选级 GO，但事件级回放 NO-GO，用户决定终止本路线，实验代码已移除  
前置结论：冻结 YOLO26s crop 线性 head 与单纯时序恢复均不满足生产要求

## 1. 目的与边界

Turhancan 在 2026-09-21 新日期审核中提议了全部 18 个确认垃圾，说明它目前适合作为高召回
候选生成器。主要问题是候选过滤：冻结 YOLO26s head 的加权精度仅 16.6%，在 01022 严格 ROI
内每 tick 仍放行中位数 20 个候选；时间重复又会把立牌、桌面和井盖恢复出来。

本实验只回答一个问题：利用已经完成的 2,460 张人工卡片，换成能同时看目标局部和周边环境的
迁移学习分类器，是否可以在保留肉眼明显垃圾的同时大幅删除固定设施和纹理候选。

本轮不改 Turhancan、不训练定位头、不接生产、不要求用户重新画框。

## 2. 数据集

六轮人工审核合计：

| 标签 | 数量 | 用途 |
| --- | ---: | --- |
| `LITTER` | 189 | 正例 |
| `NON_LITTER` | 2,083 | 负例和困难负例 |
| `UNCERTAIN` | 153 | 排除 |
| `BOX_WRONG` | 35 | 排除；不能当负例 |

每张卡已有候选框、crop、context、摄像头、时间、文件和帧身份。输入做成两个视图：

1. `crop`：候选框四周扩 15%～25%，看物体本身；
2. `context`：候选框四周扩约 3 倍，至少覆盖 96×96 原生区域，看它是否属于井盖、桌子、
   招牌、车辆或店铺设施。

同一摄像头、同一 PS、相近位置与时间的候选先聚为 `event_group_id`。所有切分按组进行，禁止
相邻帧中的同一物体同时出现在训练和验证中。感知哈希近重复也必须留在同一侧。

冻结 2026-09-21 的 300 张新日期 Shadow 为最终测试集，绝不用于阈值、模型或增强选择。

## 3. 两级实验，最多一次微调

### Level A：冻结通用视觉特征探针

先比较两个低成本特征，不更新骨干权重：

- 当前 YOLO26s crop 特征，作为已知基线；
- 一个通用图像预训练骨干的 crop + context 特征，优先 `convnext_tiny` 或 `dinov2_vits14`，
  以服务器能稳定获取并可导出为准。

分别对 crop/context 提取 embedding，拼接后只训练带 class weight 的逻辑回归。训练数据采用
按 event group 的逐摄像头 OOF。阈值只由训练/校准部分选择，目标是明显垃圾召回优先。

Level A 的意义是用几十分钟判断“现有标签在更合适的视觉特征里是否可分”。若排序仍不可用，
不值得直接进行长时间端到端训练。

### Level B：一次轻量微调

只有 Level A 同时达到以下筛选条件才进行：

- OOF 可见垃圾召回至少 90%；
- OOF 加权负例削减至少 60%；
- 各摄像头不存在成片分数倒置；
- 2026-09-21 测试集在冻结阈值下至少命中 17/18 个垃圾。

Level B 只微调表现最好的一个骨干。先冻结大部分层训练分类头，再解冻最后一个 stage，用较小
学习率训练；最多 20～30 epoch，按 group validation 的 PR-AUC 和 90% 召回下负例削减早停。
不做大规模超参数搜索。

## 4. 事件级验证

候选级通过后，必须回到真实视频链验证，不能只报卡片准确率：

1. 用冻结的新分类器重放 01022 完整 5 分钟和 01027 60 秒；
2. 所有候选统一经过 3 秒 3-hit 状态机，不让分类器通过的框直接闪现；
3. 白纸必须形成确认事件；
4. 立牌、桌面、井盖不得形成事件；
5. 再抽取五路不同时间的严格 ROI 窗口，先做 5 分钟筛查，再决定是否扩到小时级 Shadow。

短片只用于筛查。生产门槛仍以独立时段人工审核后的事件率计算。

## 5. 冻结 Go/No-Go 与停损

最终新日期测试和事件回放同时满足才允许进入长时间 Shadow：

- 可见垃圾召回 `>= 90%`；18 个正例时等价于至少 17 个命中；
- 加权负例削减 `>= 80%`；
- 01022 白纸保留；
- 01022 已知三个固定设施事件全部被抑制；
- 01027 保持 0 事件；
- 分类 P95 `<= 150 ms/tick`，latest-wins 队列深度为 1。

若 Level A 排序失败，或 Level B 后仍达不到召回与 80% 负例削减，本路线立即停止。下一步只剩
两种合理选择：补充更多独立现场正事件后训练一类小目标 detector，或接受更高人工审核量。
不得继续用更长 hold、更多阈值或 Profile 修补分类能力。

## 6. 实施步骤

1. 写数据审计器，统一六轮 review schema，校验所有 crop/context 文件、标签和源身份；
2. 生成冻结 `DATASET_MANIFEST.json`，计算 event group 与近重复组，输出泄漏检查；
3. 写 `probe` 命令确认 GPU、骨干、输入尺寸和单 batch 显存；
4. 用户按操作手册运行 Level A，保存 embedding、OOF 预测、阈值和完整报告；
5. 架构审核 Level A；达到条件后，用户再运行唯一一次 Level B；
6. 冻结模型后才读取 2026-09-21 测试标签并生成 `HOLDOUT_RESULTS.json`；
7. 通过候选级门槛后运行两段冻结视频回放；
8. 最后才决定是否开发生产旁路 adapter。

所有输出必须包含代码版本、模型来源和许可证、输入 manifest SHA-256、随机种子、GPU 型号、训练
曲线、逐样本预测与校验和。服务器仍使用 `~/ground-litter-audit` 隔离目录，临时 PS 处理后删除。

## 7. Level A 实测结果

冻结 YOLO26s 特征在 2026-09-21 新日期只达到 8/10 肉眼明显垃圾召回和 55.5% 非垃圾削减，
判定 `LEVEL_A_NO_GO`。

冻结 ConvNeXt-Tiny 特征的最佳表示为 `camera_specific_crop_context`。它在 2026-09-20 验证集
达到 45/48（93.75%）肉眼明显垃圾召回和 65.86% 非垃圾削减；冻结后一次读取 2026-09-21，
达到 9/10（90.0%）召回和 63.97% 非垃圾削减。最终 ROI 的全部垃圾为 5/5，肉眼明显垃圾为
2/2，非垃圾削减 66.67%。据预注册规则判定 `LEVEL_A_GO`。

这只允许继续验证。最终 ROI 正例数量过少，且 64% 尚未达到生产要求的 80%。为减少用户投入，
在正式微调前先增加一次冻结 head 的严格 ROI + actor filter + 三次命中事件回放；实施契约见
`2026-09-22-ground-litter-convnext-event-replay.md`。

## 8. 终止结论

01022 完整 299 秒回放保留了已知白纸，但形成 46 个确认事件；只有 1 个事件与白纸锚点重合。
分类 P95 为 477 ms。01027 的 60 秒负样本为 0 事件，但该摄像头没有独立测试正例，不能证明
召回。候选级正向信号没有转化为可用事件流，因此本路线没有进入 Level B 微调。

该回放没有消费生产配置中的 overlay exclusion，部分画面叠字事件本可由几何排除；最终 ROI
独立正例也很少。因此结论是“当前实现和证据不足以继续投入”，不外推为所有上下文分类方法都
不可能。按用户决定，相关数据构建、特征探针和事件回放实验代码已移除，原 YOLO 回放器恢复。
