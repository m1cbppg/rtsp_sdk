## 1. 业务目标和容错

用户提供摄像头与时间范围，通过回放文件接口自动获取 PS；也兼容已有七天 PS 目录。系统自动完成抽样、背景合成、选择 N、输出参考库和质量报告，不要求用户手动下载。复用同一摄像头/同一 view 的已有多边形 ROI，不要求用户挑参考图或标注白天/晚上/天气；不能因使用同一个平台就把别的摄像头 ROI 直接套过来。

用户已明确允许：一个垃圾在七天中始终存在，最终被归入背景、prior 无法检出，可以接受；极小误差和极低概率问题不作为首版阻塞条件。因此本方案生成的是**稳定场景参考**，不要求证明每个像素绝对没有垃圾。`reference` 与背景可用性不得被宣传成百分之百的清洁真值。

仍需处理常见问题：行人车辆留下背景残影、阴影造成整片误报、短期物体形成独立 Profile、新增小垃圾被容差抹去、只覆盖中午而夜间失效。不要求零误报，也不为每个疑似静止物体增加人工审批。

垃圾模型与 prior 继续各自独立召回。垃圾模型未检出不阻止 Profile 生成；长期静止物体成为参考后，semantic 仍有机会独立识别它。

## 2. 最终交付与两方案接口

输入二选一：`回放列表接口 + deviceCode + 起止时间 + camera_id`，或 `本地 PS 根目录 + camera_id`；共同需要已有 ROI/排除区与输出分析尺寸。当前生产旁路为 1920×1080 时生成相同分析尺寸。小图仅用于检索，背景合成/小目标验证使用从 PS 解码的高清帧，不能从预览图放大还原。远程 PS 是有界临时缓存，可按 §4.4～§4.8 删除；用户提供的本地源文件默认只读、不自动删除。

输出为不可变版本目录：

```text
<bank_id>/<version>/
  bank.json
  camera_geometry.json
  matcher.json
  profiles/
    p0001/
      profile.json
      reference.png
      valid_mask.png
      noise.npz
      descriptor.npz
    p0002/...
  reports/
    inventory.jsonl
    coverage.json
    profile_contact_sheet.jpg
    REVIEW.md
```

资产契约（两方案必须共用，不各写一份近似格式）：

| 资产 | 必须包含 |
|---|---|
| `bank.json` | `kind=ground_litter_profile_bank`、`schema_version=1`、bank/version/camera/view ID、profile 清单、资源限制、各资产 SHA-256、容错约定 |
| `camera_geometry.json` | 共同画布尺寸、ROI、排除区、稳定匹配区域、几何基准及配准参数 |
| `matcher.json` | 特征/算法版本、公共标准化尺度、评分权重、进入/保持包络、分批扩展检索、切换/恢复/冷却参数、掩膜规则及校准来源 |
| `profile.json` | `profile_id`、view/尺寸、样本数/有效时间块数、有效地面比例、适用分布统计、输入来源、各文件散列 |
| `reference.png` | BGR/RGB 约定明确、无损保存的完整分析尺寸背景 |
| `valid_mask.png` | 0/255；表示有足够稳定背景观测的地面，不代表法律或人工清洁认证 |
| `noise.npz` | signature/luminance 的中位数、MAD、Q95、有效时间块支持数、超 cap 比例；持久偏差诊断与四项阈值图，保存 dtype、坐标与算法版本 |
| `descriptor.npz` | 多位置亮度/色度/结构摘要及权重，小图粗匹配用 |

旧 V3.2 `daylight_tolerance.png` 是二值图，不能直接塞入连续噪声值。新 Bank 由专用 loader/adapter 读取，旧单 Profile 格式保持兼容。

`valid_mask` 在构建完成时冻结；在线新增物体不能反过来改写它。离线噪声图也不允许随直播残差增长，在线掩膜与可用性遵守方案二 §5.1。`reports/coverage.json` 必须同时含静态潜在覆盖、完整 Selector 的动态覆盖、暂停区间、切换时延和保留/删除 Profile 的理由。

## 3. 算法总流程

```text
远程文件清单/本地 PS 清点与时间恢复
 -> 按处理需求获取一小批 PS（缓存有界）
 -> 稀疏样本与质量过滤
 -> 同视角配准、分块外观特征
 -> 自动生成代表组
 -> 按时间均衡取高清帧
 -> 遮挡过滤 + 稳健时间背景合成
 -> 估计有限噪声容差
 -> 在独立片段上测静态潜在覆盖
 -> 贪心预选 N、补采缺口
 -> 完整 Selector 时序回放、保留过渡参考、动态剪枝
 -> 冻结 Bank 与报告
```

核心算法选择：**空间分块描述子 + 自适应代表点聚类 + 按时间块均衡的时间中位数 + 实际观测块替换 + 贪心覆盖压缩**。首版不训练新的大模型，不使用生成式补图，不做复杂的逐物体清洁身份推理。

素材获取与建库解耦：每个处理阶段都可以“临近使用时刷新 URL→下载少量文件→完成该阶段处理→提交产物→释放 PS”。后续阶段通过稳定文件身份按需重拉，不能要求七天 PS 同时在磁盘上。

## 4. 文件扫描与抽样

### 4.1 目录和时间

远程模式先查询全部目标时段的文件元数据，本地模式扫描路径和大小；编码、分辨率、可读时间范围在文件实际到达后探测。时间优先来自接口记录起止时间/可解析文件名/导出信息，必要时对少量画面做 OSD OCR 校正。PS 内 PTS 可能重置，不能直接当绝对日期。

用 SQLite 记录作业、失败原因和缓存。用户本地源文件只读；远程缓存由专用租约管理器释放。本地先使用 stat 与弱指纹索引，实际用于构建的文件计算完整 SHA-256；远程下载时边写边计算完整 SHA-256，未下载完不得标成完整校验。缓存过期时仅重跑相关阶段。

处理重复下载和重叠录像；同一时段的重复帧不增加样本权重。少量损坏文件进入跳过清单；大段时间缺失在报告中显示，不因此要求人工逐文件修复。

时间恢复/去重后先按 §8 划分构建、校准和盲测清单，再做外观发现与统计。第七天可以做容器可读性检查，但其图像、特征分布、几何基准与噪声统计不能提前参与选组/调参。跨日文件按时间范围划分，不能因整文件随机分配造成泄漏。

### 4.2 粗采样

每个五分钟文件先取约 5s、150s、295s 和一个可复现随机时刻。实际时长不足时按比例调整。七天完整录像约 2016 个文件，对应约 8064 张初始预览图。

上述为全流程总量：前五天约 5760 张用于发现外观，第六天约 1152 张用于校准粗覆盖，第七天约 1152 张只在冻结后用于评价；连续时序评估另按分析节拍取帧。不能把七天 8064 张一起聚类后仍称第七天为盲测。

预览图宽 640～960，保存外观特征、质量分数与来源时间。普通区域不重复高清推理，以下片段自动加密到每 30s 或 5s：邻帧外观突变、新状态无参考、候选背景遮挡严重、时间定位不可靠。

用于合成的片段按需追加 10～30s 短窗口，取得运动/遮挡证据。不得把粗采样截图直接当作连续生命周期测试。

PS 的 seek 成本必须先实测：有些文件需要从前一个可定位点解码。优先同文件一次取完所需时间点；定位低效时使用单次顺序解码。少抽图主要节省推理与存储，不能承诺同等比例节省解码。[FFmpeg 定位说明](https://ffmpeg.org/ffmpeg.html#Main-options)

### 4.3 质量与视角

剔除明显黑屏、严重模糊/过曝、花屏和不可解码帧。冻结不通过“连续几张图一样”单独判断，避免误删静止场景；结合 OSD/PTS 进展或明显重复码流证据。

复用已有特征点配准。小抖动对齐至共同画布；大幅转动/变焦另分 view，首版只发布与当前目标机位一致的一组。仅颜色/红外变化不自动视为机位移动。

### 4.4 已核实的回放文件接口

请求方式：POST；Content-Type：application/json。

```text
https://qyzcapi.dgjx0769.com/ims-mainte-pc/p-api/v1/monitor/play/ctseelink/playback/file-urls
```

```json
{
  "deviceCode": "44180209031322001030",
  "startTime": "2026-09-15 00:00:00",
  "endTime": "2026-09-15 01:00:00"
}
```

本轮只查询上述一小时元数据，没有下载 PS。实测 HTTP 200、业务 code=200，data 为 12 项数组，均无 errorMessage。单项字段：fileId、fileName、recordStartTime、recordEndTime、fileSize（数字字符串）、fileType、url、urlExpireSeconds、errorMessage。不得套用现有 playback/rtsp/by-time 的 RTSP 响应解析器。

约 403s 后再次请求同一小时，仍返回 12 项，fileId/大小/起止时间全部相同，12 个 URL 全部更新且有效期仍为 120s。这验证了同一文件清单的地址刷新与本次 ID 稳定性；未访问媒体本体，不能据此声称媒体重拉/未来保留期限已验证。带签名的临时原始响应已清理，不进入交付包。

| 实测项 | 结果与设计影响 |
|---|---|
| 临时下载地址有效期 | 12 项均为 urlExpireSeconds=120；必须即时刷新，不能把查询时拿到的七天链接排成长队 |
| 录像长度 | 本次 303～304s，不能硬编码恰好 300s |
| 返回实际范围 | 2026-09-14 23:59:44 至 2026-09-15 01:00:31，包含查询区间之外的首尾；按真实时间与处理范围取交集 |
| 大小 | 合计 749,501,533 bytes；单项 51,111,427～80,344,109 bytes；约 70MB 只是估计 |
| 片段边界 | 本次相邻记录首尾连续；其他时段仍需检查重叠/缺口 |

本次给定请求无需额外鉴权头即成功，不代表所有部署始终如此；来源适配器允许从运行配置注入鉴权。URL 内含签名参数，不写入公开日志、版本库或最终报告；下载到其他域名时不自动转发平台鉴权头。索引保留 fileId/记录时间，临时 URL 只在短期下载上下文中使用。

以下尚未实测：文件实际下载/解码、HTTP Range 与断点续传、最大查询跨度/分页限制、刷新 URL 后可重拉期限、下载开始后跨过链接有效期的行为。A1 输入试点必须核实，不能从列表查询成功推定这些能力均可用。

### 4.5 元数据清单与即时下载调度

1. 固定本次目标时间范围及 Asia/Shanghai 时区配置，不使用随作业运行不断后移的“最近七天”。API 时间不带时区，试点用文件名/画面时钟核实。
2. 按一小时窗口查询，邻窗可重叠约五分钟；按 deviceCode+fileId 去重，而非按 URL、整点或列表下标去重。保存记录真实时间、大小、查询窗口、响应状态与来源版本。跨集合边界的文件可重复物理读取，但帧按所属时间集隔离。
3. 单个一小时返回 12 项不证明整个 API 无截断。试点比较一小时结果与两个半小时结果的文件 ID 并集；若存在分页字段则翻页，受限时缩小窗口；查询失败与“成功但无录像”分开记录。
4. 清单只保留稳定定位信息。消费者即将有空位时，重新查询覆盖待处理文件的小时间窗，按 fileId 找到新 URL，再立即下载。URL 值改变不产生新的录像条目。
5. 用请求发起的单调时间加 urlExpireSeconds 保守计算有效期；起步要求开始下载前至少剩余 30s，否则刷新。下载排队不跨过有效期，不能假设签名期结束一定中断/一定不中断已开始的传输。
6. 过期或鉴权失败时刷新 URL 后重试；网络错误有限退避，429 遵循服务端节流信息。起步最多三次自动尝试，失败明确记录并进入后续补采队列，不能无限重试同一文件拖住七天作业。

媒体下载到受管缓存中的 .part 文件，边接收边计算字节数与 SHA-256；完成后校验期望大小、可探测 PS/媒体内容和解码时间，再原子重命名为可消费文件。HTTP 200 也可能带业务错误正文，不能直接当 PS。断点续传只有在实测 Range、对象身份和响应范围一致后启用；未支持时删除本次失败的 .part 后重拉，不拼接两个不同版本的录像。

### 4.6 有界流水线与删除条件

```text
待处理文件 ID 清单
 -> 临近使用时刷新地址
 -> 有界下载/预取队列
 -> 当前阶段解码、抽帧/分析
 -> 产物原子落盘 + SQLite 阶段提交
 -> 释放文件租约
 -> 删除本任务下载的临时 PS
```

首版起步：一个处理消费者、最多两个下载/预取槽（下载中与等待处理合计不超过两个），即通常最多三个 PS 同时驻留；约 70MB/文件时原始缓存约 210MB，另含少量元数据。额外设置 raw_cache_budget=1GiB 的硬字节上限，包含所有 .part、预取、处理中与失败残留，按实际 fileSize 预留空间；容量不足就停止派发下载。未知大小需流式计数和限额，不能依赖文件数量限制磁盘。

高清抽样、noise、最终参考与报告也占磁盘，另设整个工作目录总预算，试点可从 20GiB 起步，按实测调整；不能宣称整套作业永远只占 210MB。用户现有源目录不计作可自动清理空间。达到预算时先释放无租约临时文件/可重拉缓存，不删除后续必需且无法重建的产物来凑额度。

下载、离线解码和造库使用独立作业进程，优先在不承载生产视频的资源上执行；同机时还要限制总下载带宽、CPU/GPU 并发并观测生产流延迟。磁盘有界不代表计算负载有界，不能把离线批量推理塞进实时旁路。

SQLite 至少分开记录 materialization 状态（ABSENT/DOWNLOADING/READY/LEASED/EVICTABLE）与每个阶段状态（preview、hd_extract、calibration_replay、blind_replay）。preview 完成后可释放 PS，但不能据此把 hd_extract 或整个文件任务记为完成。

删除必须同时满足：文件属于当前受管下载缓存；无解码器/其他消费者租约；当前阶段所需产物已落盘并校验；阶段结果已经事务提交；后续材料已提取，或来源具备可用的重拉路径。只删除本任务取得的临时副本，绝不调用远端删除接口，也不删除用户提供的本地源文件。

崩溃恢复按幂等方式完成：未提交产物不能释放源；提交后尚未删除的文件可重新清理；源已删除且阶段完成的任务跳过；后续新阶段按 ID 重拉。更新阶段键必须包含输入散列、算法版本与配置版本。重拉得到不同 SHA-256 时视为源版本变化并失效相关产物，不能覆盖后继续沿用旧成绩。

### 4.7 多轮算法如何避免囤积原始录像

| 阶段 | PS 的处理与释放 | 必须保留的材料 |
|---|---|---|
| 发现外观 | 构建日/校准日逐文件取小图、特征、质量与时间信息后释放 | 来源清单、预览/特征、质量与抽帧位置；不把小图冒充高清来源 |
| 合成/补采 | 确定代表组后按文件合并所有高清取帧/短窗口需求；一次重拉尽量完成该文件本轮全部需求，再释放 | 选中的无损高清帧、时间块摘要、遮挡/运动证据、来源散列 |
| 校准/动态定稿 | 按时间顺序重拉相关连续块，最终完整流式回放第六天；消费完前一 PS 即释放 | 时序轨迹、底层可复用统计、必要问题证据；不保留整天所有高清帧 |
| 冻结盲测 | Bank 冻结后才解码第七天评价，按生产分析节拍消费并释放 | 配置/资产版本、事件与覆盖时间线、有限证据片段和缺口 |

只有特征和缩略图不足以重新合成/评估六像素目标；被选中的素材需要从原 PS 再获取高清观测。首版接受少量按需重拉，换取低磁盘占用。无损高清帧数量和字节数均有预算，按时间均衡保留，不把压缩 JPEG 或二次有损转码当作等价源。不能为省盘削减既定目标验证或只留下成功样例。

五分钟文件只是运输切片，不是一次新实验。连续回放跨文件保留同一个 Selector、V33EventMemory、虚拟时间和事件 ID；首尾重叠按源时间去重，真实缺口按缺帧规则处理。下载等待不伪装为录像内的环境变化或真实缺帧；其墙钟耗时单独计入作业成本。读取速度与模拟在线算力分开报告。

**低磁盘占用不等于低总流量。** 普通 PS 是否支持高效远程定位尚未知；默认需要完整取得一个文件才能可靠抽取多个位置。2016×70MB 约 141GB 是七天一次全量读取的粗估，按需重拉会增加流量；该设计避免的是同时落盘这 141GB。Range/远程 seek 只有经真实文件验证后才能优化，不以减少下载字节为由漏扫整段外观。

### 4.8 重拉期限与保留策略

120s 是临时 URL 的有效期，不等于录像只保留 120s；反过来，能够刷新 URL 也不证明录像永远保留。A1 必须确认录像可重拉的期限，并估算粗扫、建库、校准所需总时长，最早的素材优先处理。

只有在计划重拉时间仍处于可用期限内，才采用“仅保留预览后释放 PS”。临近保留期限或期限未知的文件，应在释放前完成已知高清需求，或在有界缓存中暂时 pin 住并优先完成后续阶段；尚不能确定的后续需求不能靠“预览已完成”声称已保全。

如果远端即将删除大量录像、后续还需要这些录像、而本地预算又不足以保留，则“随时重算全部原片、极低磁盘、远端不可重拉”三者不能同时保证。先保全代表性高清样本与已知验证材料，剩余不可恢复范围明确列为缺口；若会损失整类环境或整段验收数据，应暂停相应阶段并报告需要的空间/保留期限，不隐瞒质量下降。此项是输入可用性约束，不是要求用户逐文件筛选。

报告至少含查询/有效文件数、下载字节/重拉字节、临时与持久产物峰值空间、URL 刷新/失败次数、缺失时段及源是否还能复取。最终 Bank 可独立供线上加载，不依赖回放接口和 PS 缓存继续存在。

## 5. 自动发现代表外观组

在小图上建立固定网格，首版可用 16×9。每个有效块计算亮度中位数、亮度四分位距、色度中位数、梯度统计；保留空间位置。匹配区域复用稳定结构及地面分区，屏蔽 OSD、可识别遮挡和明显运动块。

各维度使用整个构建集固定的稳健尺度标准化，不能每张图各自消除亮度差异；否则阴影/明暗状态会混在一起。第一版使用可解释特征，无需 CLIP/VLM 或向量数据库。

代表点算法：

1. 选质量最高且遮挡最少的一帧作为初始中心。
2. 计算每个样本到现有中心的最小距离。
3. 若某批有效样本距离超过半径且跨多个独立时间块复现，选择其中代表性最好的一帧新增中心。
4. 单独一帧的远距离异常进入补采/离群清单，不立即新增 Profile。
5. 重新分配近邻，中心更新为组内实际代表帧（medoid）。

聚类半径从相邻稳定时间块的距离分布初始化；构建阶段可从窄到宽试少量半径，以最终覆盖/库大小选取。候选数量设置上限，例如 48；最终 Bank 上限首版 24。上限是资源约束，不是预设 N。

局部新物体不应成为主要聚类特征：使用每块稳健统计和权重上限；新增中心必须带来分散背景区域的外观差异或可复现的有效适配收益。大物体/设施改变导致的少量错误分组先记为已知误差，不引入复杂对象身份系统。

## 6. 每组如何得到好的参考图

### 6.1 时间均衡选帧

从每组选择至少 6 个不连续五分钟文件，优先跨两个以上日期；常见状态起步取 60～150 张高清帧。每个五分钟文件贡献设上限，不按补采帧数增加权重。取帧不够或遮挡多时只对该组补采。

只在一天出现但跨多个不连续片段的状态也可产出参考，不强制要求三天或人工批准。支持偏少的参考标为低支持，用更严格匹配/更小可用范围上线；若实测有效就保留。相邻五分钟文件可用于合成，但不能冒充独立验证。

### 6.2 背景合成

对齐所有源帧后，按以下顺序自动处理：

1. 对选中帧运行现有 actor/context 检测，并结合短窗口运动，生成遮挡掩膜。
2. 垃圾模型框只作辅助提示；持续固定误报不能直接挖掉大片地面。带明确短期出现/消失迹象的物体才加入临时排除。
3. 每个时间块先生成一个有效观测摘要，再跨时间块计算逐像素加权时间中位数，得到稳健初稿。
4. 以初稿为指导，在重叠图块中选取“最接近初稿、清晰且未遮挡”的真实观测块作为最终颜色/纹理来源；重叠处选择差异小的接缝，避免大范围模糊混合。
5. 某块真实观测稀少或各观测差异很大时自动补采一次；仍不能构建则局部无效。大部分稳定区域直接保留，不因无法证明没有永久垃圾而失效。

这是稳健时间背景估计，假设大部分可见样本能代表正常场景。长期不变的物体可以成为背景，符合用户容错；暂态物体占某组多数时仍可能残留，应通过时间均衡、跨片段验证和简单局部异常检查减少，而不承诺绝对消除。

仅用中位数原图也可先形成基线，真实图块替换只有在接缝检查通过、细节保留更好时启用。禁止为了执行复杂方法而让背景质量比简单基线更差。

### 6.3 噪声与有效区域

对来源之外的构建集时间块做与运行时相同的受限补偿，在 `residual_maps()` 的 signature/luminance 量纲中分别计算中位数 m、MAD、Q95、超 cap 比例与支持时间块数。每个块按时间计权，排除独立的人车遮挡和瞬时运动；不能通过丢弃所有高残差样本使统计看起来正常。

首版继承 V3.3 的目标尺寸、种子/支持基础值和时序参数；采用以下有限噪声修正，并将持续偏差诊断与阈值计算分开：

```text
raw_T_p(x) = max(T_base, m_p(x) + max(k × MAD_p(x), epsilon))
stored_T_p(x) = min(raw_T_p(x), T_cap)

bias_flag = raw_T_p(x) > T_cap
         或 Q95/超 cap 比例达到构建质量诊断条件
```

`k` 起步 2；epsilon 为正，signature 起步 0.05、luminance 起步 1.0，避免恒定残差刚好等于门槛仍触发 `>=`。支持不足时使用基础阈值并标明低支持，不估计没有证据的尾部分位数。

对 bias_flag 的连通区域、重复时间块和越界强度生成诊断。零星越界只是质量提示；跨多个独立时间块持续出现、覆盖明显区域的偏差必须进入“重对齐→重合成/细分外观组→局部不可靠”的自动处理，起步最多两轮。`stored_T` 被截断不等于该处已合格，不得带着严重 bias_flag 仍计完整覆盖。

局部不可靠是离线构建资产的质量结论，必须保留来源和所损失面积；不能在直播时把新目标标成 bias_flag 然后自动挖掉。若一个物体七天始终存在，合成参考通常会包含它，本身不构成必须剔除的偏差。

首版上限直接采用现有 V3.2 噪声区的最大增量，不先扩大敏感度范围；当前代码起点如下，实施时再次核对：

| 阈值图 | T_base | T_cap |
|---|---:|---:|
| seed signature | 3.0 | 3.8 |
| seed luminance | 100.0 | 130.0 |
| support signature | 1.2 | 1.45 |
| support luminance | 25.0 | 33.0 |

残差中心、Q95、MAD 和正余量必须一起测试；包含“30 次相同大残差、MAD=0”的回归。增加容差和新增 Profile 是两件事；环境不适配优先换参考，不继续抬高小目标门槛。

运行时连续噪声阈值由新 adapter 消费；不得默默改旧 V3.2 阈值。noise 估计依赖共享的有限补偿实现，离线与在线必须同版本。

## 7. 自动确定 N

先用独立时间块验证每个候选能否被方案二的**共享 stateless 匹配器**接受，再验证它的单帧 prior 分析可用。构建集内部使用完整时间块留出或按天交叉验证；被用于合成/噪声估计的原帧不能给自己提供覆盖成绩。

一张 profile 的“好”包括：参考不明显重影、有效地面足够、能覆盖独立片段、能保留测试小目标。出现七天始终存在的固定物不构成失败。

N 的选择分为静态预选与动态定稿。贪心只生成起步集合：

```text
B = 空集合
循环：
  计算每个候选加入 B 后，按单帧唯一分配新增的时间×地面有效覆盖
  扣除库大小/支持不足的固定成本
  添加收益最大的合格候选
  若达到覆盖目标，或无显著正收益，或达到资源上限：停止
暂存：看起来冗余的候选；此时不做最终删除
```

同一帧必须只分配一个 Profile，不能拼 A 的左边和 B 的右边计算覆盖。未被选中的候选仍保留于离线缓存，补采/调参不必重建全部。

### 7.1 动态定稿与过渡参考

在构建集的独立连续块及第六天上运行方案二的**同一个有状态 Selector**，包括检索扩展、加载就绪状态、连续确认、驻留、冷却、候选全尺寸验证、证据重置。给定缓存/耗时预算模拟时必须注明；服务器实测前不得把“所有资产零时延”回放当真实性能。

最终优化指标为：

```text
J(B) = 动态不可用的时间×地面权重
     + λ × Profile 数量
     + μ × 过长暂停/频繁切换成本
```

约束为：小目标测试不系统性退化、主链预算不超限、不以扩大噪声上限换覆盖。权重和暂停预算在第七天盲测前冻结。

先对暂停最集中的时段试加入未选候选或补采更宽适用范围的代表，再尝试逐个删除冗余。只有动态回放的有效覆盖、暂停尾部和确认延迟均未明显变差，才删除对应参考。只在过渡时起作用的参考即使没有新增静态覆盖，也可以保留。

每次变更不必重算全部图像：可缓存与配置、参考、帧、几何和掩膜摘要绑定的底层特征；有事件掩膜依赖的匹配、状态机和证据必须重新计算，不能复用另一次选择轨迹的最终结果。

控制构建成本：先在稀疏留出样本上用小图淘汰明显不适用候选，再做单帧高清检查；动态优化先集中回放过渡/暂停连续块，最终候选必须完整回放校准日与盲测日。解码按时间顺序流式执行，缓存特征和必要的中间统计，不把整天高清帧全部常驻内存。连续评估会读取对应录像并解码；粗采样节约的是前期构建成本，不能把它当作无需完整时序验收的理由。

### 7.2 统一统计口径

- `potential_coverage`：每帧是否存在某张合格参考，只表示库的潜在能力。
- `effective_prior_coverage`：实际 Selector 选中、当前帧分析完成且结果新鲜的可判断面积，按真实时间计权。
- `prior_pause_p95/max`：连续无法提供 prior 新证据的区间，逐小时和地面分区统计。
- `switch_count`、首次发现到提交时延、首次新增目标到确认时延；确认失败也计入结果。

时间覆盖不使用未封顶的前向填充：某 tick 有效只代表到下一计划观察点或该结果新鲜度截止点之前，取较早者；缺帧、预算跳过、验证失败均作为缺口。更精确的已知曝光区间可以替换这一估计，但必须一致地用于所有对照。

上述为采样时间轴上的有效观测覆盖，不表示结果在采集瞬间已发布。运行时另记采集、分析完成和实际提交时间，统计实际 UNKNOWN 时长、恢复到发布的等待与端到端确认延迟；候选仍在准备/计算时不能回填为已经恢复。离线的加载/耗时模型、实际服务器墙钟测量分列，不能拿零时延模拟代替在线体验。

时间样本按代表时长加权，商户地面分区分别统计。主观不命名天气，但自动发现的少见稳定外观组需独立报告；不能用大量中午帧遮住整段夜间不可用。

默认试点目标为可见、画质合格地面的动态时间×面积有效覆盖 95%，不是已验证保证。完整业务 ROI 的覆盖同时报告。不能通过缩小 ROI、加大容差或把未知画面从业务总分母删除来达标。仍有少量未覆盖时直接输出缺口及候选库，不要求必须 100% 才交付。

自动补采最多若干轮，起步两轮；补采预算/最大轮数可配。新增收益很小则停止，剩余小概率失败放入后续问题清单。

## 8. 七天数据如何使用与验证

首轮：前五天构建/内部时间块验证，第六天校准匹配/覆盖参数，第七天冻结盲测。第七天图像不能提前参与外观发现或调参；重复、重叠录像不能跨集合。

盲测按生产分析节拍连续流式回放，包含真实时间戳、间隔与方案二的证据管理，另抽查无事件时段。报告静态/动态两种覆盖、按小时/分区缺口、暂停与恢复时延、新增目标测试、误报样例和算力成本。未人工核实的候选只能称“待审核”，不能自动算真/假垃圾。第六天可选择库组合，第七天只评价，发现问题后不得一边调参一边保留“盲测”称谓。

验收侧重改善幅度与常见场景：

- 与现有单下午 Profile 对照，全天有效覆盖明显提高。
- 真实已知小目标及结构测试中，不能出现普遍被背景/高容差吸收的退化；小样本逐例报告，不夸大总体准确率。
- 常见人车经过、阴影变化、无垃圾片段不出现持续大面积误报；少量剩余误报列出即可，不设零误报闸门。
- 七天始终存在的垃圾被背景吸收明确记为允许偏差，不要求修复或人工补图。

通过后可以直接使用冻结库。若再用全部七天重建则生成新版本，原第七天不再独立；新版本需用后续独立录像/影子运行确认，不能继承旧版盲测成绩。

## 10. 人工参与与首版范围

复用同一摄像头已有 ROI 时，用户只提供设备/时间范围，或已有文件目录。模型、下载/清理、抽帧、分组、合成、选 N、报告均自动执行；少量歧义默认按稳定背景处理或局部跳过，不弹出逐物体审批。

报告自动展示 N 张参考与缺口缩略图，执行者可集中快速检查。只有无法识别摄像头、视角确实改变或缺少业务 ROI 时才需要用户补充信息。新机位 ROI 自动建议可后做，不影响当前机位。

首版暂不做：永驻垃圾识别、全自动语义清洁认证、天气标签、逐物体背景账本、生成式修复、在线自更新参考、多个机位自动迁移、为极端低概率场景反复加 Profile。
