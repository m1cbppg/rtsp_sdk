# 固定监控误报重复性可行性审计

日期：2026-09-22  
状态：执行中；只读使用现有人工标签，不训练、不接生产

## 目标

验证五路固定监控中的误报是否集中在少数位置和少数外观模式。如果少量重复簇覆盖大部分误报，
则“共享视觉模型 + 每摄像头轻量适配”的路线具备现实价值；如果误报大多是互不相同的瞬态模式，
则不能指望只靠记住困难负例解决。

## 输入

使用已经人工完成的六轮审核。只读取 `NON_LITTER`；`LITTER`、`UNCERTAIN`、`BOX_WRONG` 不参与
误报簇统计。分别报告：

1. 历史候选全集；
2. 候选中心落在用户最终 ROI 内的生产相关子集。

全集用于训练共享分类器，最终 ROI 子集用于判断当前五路部署的实际收益。不能让道路和车辆等
ROI 外负例夸大可解决比例。

## 三种重复口径

1. **精确重复**：crop 文件 SHA-256 完全一致；只说明资产重复，属于保守下界。
2. **位置重复**：同摄像头、归一化中心距离不超过画面对角线约 2%，且框面积尺度相近；衡量固定
   位置是否反复出候选。
3. **位置 + 外观重复**：在位置重复基础上，crop 或 context 的 64 位感知哈希距离不超过 12；
   用于降低相邻但不同物体被合并的风险。

同时做阈值敏感性：位置半径 1%、2%、3%，不能只挑一个最有利阈值。

## 判定

- 若严格的“位置 + 外观”口径下，Top-20 簇覆盖最终 ROI 负例至少 60%，或 Top-50 覆盖至少
  80%，判为 **集中型误报**，允许进入上下文分类器实验。
- 覆盖在 40%～60% 为混合型，只允许做小规模探针，不直接微调。
- Top-50 仍低于 60% 为分散型，摄像头特定记忆收益有限，应优先训练更强通用检测/分类模型。

该结论只说明负例结构是否可学，不证明模型已经能够学会，也不替代独立日期验证。

## 视角变化边界

主结论不得依赖绝对坐标永久有效。位置聚类用于发现和采样困难负例；正式分类器以 crop 和 context
外观为主。摄像头移动后创建新的 `scene_version`，清空位置缓存并重新跑短审计，共享模型继续使用。

## 交付

- `CLUSTERS.json`：逐簇成员、代表样本、日期和数据集跨度；
- `REPORT.md`：全集与最终 ROI 子集的覆盖率和判定；
- Top 簇 contact sheet；
- 输入文件和输出的 SHA-256；
- 缺失资产与异常 bbox 清单。
