# 现场小垃圾检测模型路线与实施计划

日期：2026-09-21
状态：**下一条推荐路线；尚未训练、尚未接入生产**

决策依据：[背景 Profile 先验路线 NO-GO](../decisions/2026-09-21-ground-litter-profile-prior-no-go.md)。

## 1. 业务目标

在指定多边形 ROI 内检测：

1. 袋装垃圾、塑料袋、瓶子、罐子等现有垃圾模型本来能够识别的目标；
2. 纸片、小包装、零散碎屑等现有模型容易遗漏的目标；
3. 极小且肉眼难以稳定确认的目标允许忽略，首版不承诺原生短边小于 8px 的目标。

允许少量遗留误报，但要能测量和定位。最终结果以“独立垃圾事件”为单位评估，不能只看单帧 mAP，也不能用训练素材上的演示代替独立日盲测。

## 2. 总体架构

```text
最新帧
  ├─ 现有 turhancan 语义通道：袋装垃圾、瓶罐、塑料袋等
  └─ ROI 原生分辨率透视分块
       └─ 现场小垃圾检测器：统一类别 ground_litter
            └─ 可选轻量二分类复核器（仅在误报成为主矛盾时增加）

两路候选
  -> 几何去重 / 同目标合并
  -> 可选的共同 hard-negative 复核器
  -> actor/context 排除与可见性判断
  -> V3.3 时间状态机
  -> confirmed 事件与显示框
```

两路独立召回。现有语义模型不需要小垃圾模型背书，小垃圾模型也不要求 Clean Reference 或 Profile 语义背书。Profile Bank 不在新路线的检测关键路径中。

## 3. 模型选择

首个基线使用仓库已有的 `yolo26s.pt` 做一类目标检测微调，类别只有：

```yaml
0: ground_litter
```

首版选择 detection 而非 segmentation，原因是小目标掩膜标注成本高、边界不稳定，业务最终只需要事件框和位置。`yolo26s.pt` 已在当前运行环境出现，部署风险小；是否替换为其他骨干必须由相同盲测集上的召回、误报和时延结果决定，不能先做大范围模型选型。

若检测器事件召回已达标但硬负例误报仍高，再训练一个小型 `litter / non_litter` 裁剪二分类器作为候选复核。它不能作为第一阶段前置依赖，也不能用来补一个本身没有召回的检测器。如果实测表明误报主要来自现有 `turhancan` 通道，复核器需要同时评估两路候选，而不是只清理新模型；高置信的已知正常垃圾是否绕过复核器，由冻结验证集决定。

## 4. 分辨率与 ROI 算法

不要把 2560×1440 全帧直接缩到 640 后检测。只处理 ROI，并依据透视尺度分层切块：

| 区域 | 原生切块建议 | 推理输入 | 重叠 |
| --- | ---: | ---: | ---: |
| 远区 | 256～320px | 640 | 20%～25% |
| 中区 | 320～416px | 640 | 20%～25% |
| 近区 | 416～512px | 640 | 20%～25% |

切块边界沿用摄像头真实多边形 ROI；框中心必须落在 ROI，有效面积比例不足的框丢弃。跨 tile 结果映射回原图后做 class-agnostic NMS 或 WBF，再进入状态机。

目标尺寸分级：

- 原生短边 `<8px`：忽略，不计首版漏检；
- `8～11px`：挑战集，只报告，不作为发布阻塞；
- `≥12px`：首版正式验收集；
- 每个透视分区单独报告，避免近区大目标掩盖远区失败。

具体切块大小要用标注集自动检查“目标经缩放后的像素尺寸”和 GPU 时延，允许在上述范围内调整一次。

## 5. 数据来源

七天 PS 仍然有价值，但用途从“造 Profile”改为“造现场数据集”。沿用已经完成的有界流程：拉取一个 PS、抽帧/处理、保存必要产物、删除临时 PS，不需要一次下载 129GB。

### 5.1 现场真实数据

- 从 7 天回放按日期、小时和外观变化抽取 ROI 帧，覆盖白天、傍晚、夜间、阴影、雨后、车辆遮挡和保洁过程；
- 大量真实无垃圾帧作为 hard negative，保留货架、反光、井盖、地砖缝、车辆边缘、扫把、桶等易误报物；
- 用现有 `turhancan`、V3.3 候选和简单运动/变化候选做数据挖掘，只负责提议，不自动成为正标签；
- 相邻帧中的同一物体通过跟踪聚成一个事件，审核一次后传播到同事件帧，再抽查传播结果。

### 5.2 公共垃圾数据

优先使用 TACO 等带框/掩膜的公开垃圾数据，把细分类映射为 `ground_litter`。使用前记录数据版本、许可证和来源。公共数据用于增加瓶罐、纸张、包装和塑料外观多样性，不能替代现场盲测。

### 5.3 合成数据

把公共数据或已确认真实垃圾的透明 cutout 合成到现场空背景：

- 按远、中、近区透视缩放，重点生成 8～32px 短边目标；
- 匹配局部亮度、色温、阴影方向、模糊、H.265 压缩和部分遮挡；
- 标签由合成过程精确生成；
- 同一个 cutout、背景文件或连续事件不能跨训练/验证/测试集合。

合成数据负责补覆盖，不负责最终验收。模型只有在真实现场正样本盲测上通过，才能宣称有效。

### 5.4 七天回放的自动筛选算法

不能只运行现有垃圾模型再标它找到的目标，否则数据集会继承现有模型的漏检。按下面四路并行提议，再统一去重：

1. **语义路**：现有 `turhancan` 低阈值运行，找瓶罐、袋装物和塑料类候选；
2. **短时变化路**：在同一 PS 内做稳像后的短时前景提议，只用于找到可能的放下/清走时刻；
3. **跨时变化路**：同一位置跨 5～60 分钟比较，找持续出现的小物体；虽然它不适合作为最终检测器，仍可用作高召回数据挖掘器；
4. **分层代表帧路**：按小时、亮度、阴影、湿地反光和 ROI 外观聚类，每个簇抽代表帧，覆盖前三路共同漏掉的静态目标。

所有提议按空间 IoU、时间邻近和视觉 embedding 聚成“候选事件”。每个事件只保留首帧、峰值帧、末帧和前后背景帧组成 contact sheet；人工只审事件，不逐帧审视频。未被任何提议覆盖的代表帧还要随机抽检，估算候选生成阶段的漏检率。

处理必须流式进行：每次获取一个约 5 分钟 PS，在本地临时目录解码低频帧和候选附近短片段，写出候选、必要帧、特征和 manifest 后立即释放原始 PS。作业保存 `fileId + 时间范围 + SHA-256 + 处理版本`，支持断点续跑且不重复下载已完成文件。

## 6. 标注方案与人工量

采用一类矩形框。标注规则：框住属于垃圾的可见部分；被遮挡超过约 70% 或人工无法判断时标为 `ignore`；固定经营物、扫把、桶、路面设施和车辆不标正例。

审核界面以事件 contact sheet 为单位，给出三个按钮：`垃圾`、`非垃圾`、`不确定`。不确定样本不进入训练正负集。通过跟踪和近重复聚类，避免逐帧审核。

自动标签的可信顺序：

1. 合成目标的自动标签：可直接使用但抽检；
2. 公共数据原始标签：映射后抽检；
3. 现有模型/候选挖掘：必须人工确认；
4. 背景差分候选：只能作为待审样本或困难负例来源，禁止自动标成垃圾。

最小可行数据目标不是硬凑数量，而是覆盖独立事件：

- 现场独立真实正事件：优先达到 50～100 个；若七天内不足，如实记录；
- 公共正实例：约 500～1500；
- 合成正实例：约 2000～5000；
- 现场负帧：约 3000～8000，并保留困难负例标签来源。

如果当前七天没有足够真实正事件，可以训练原型并进入无显示框的 shadow 模式采集候选，但不能完成准确率验收。

为控制人工量，第一阶段先审核高置信候选和各外观簇代表样本，目标是约 200～500 个候选事件，而不是数万帧。若抽检显示候选生成召回不足，再补抽样；不能默认“未被模型提议”等于无垃圾。

## 7. 数据切分与防泄漏

按日期、PS 文件和垃圾事件分组切分，不能随机拆相邻帧。建议：

- 训练：较早日期；
- 校准/验证：独立日期；
- 最终盲测：完整保留的独立日期或后续 shadow 新数据；
- 同一垃圾事件、同一合成 cutout、同一背景帧只出现在一个集合。

最终测试集一旦冻结，不再用于调阈值、挑模型或选择增强参数。每次训练保存数据 manifest、代码提交、权重散列和完整配置。

## 8. 训练与两轮上限

第一轮只做可判定的基线：

- `yolo26s.pt` 初始化；
- `imgsz=640`，训练数据与线上 tile 尺度一致；
- 约 100 epochs，early stopping；
- 使用轻量颜色、亮度、模糊、压缩、尺度增强；
- 控制 mosaic 和强透视，避免把本已很小的目标继续破坏；
- 类别只有 `ground_litter`，报告尺寸分层指标。

第一轮盲测后只允许一次基于真实错误的 hard-negative / 漏检补样再训练。第二轮仍达不到停损门槛，就暂停模型工程，复核像素下限、摄像头视角和业务要求，不进入无限调参。

## 9. 评估口径和 Go/No-Go

训练前先跑三套冻结基线：现有 `turhancan` 单独、现场小垃圾模型单独、两者融合。所有指标按来源拆分，才能判断正常垃圾能力是否保住，以及新增误报来自哪一路。

### 9.1 离线门槛

在冻结的真实现场盲测集上：

- `≥12px` 独立垃圾事件召回率：**≥70%**；
- 现有语义模型已经能识别的袋装垃圾、瓶罐和塑料袋，融合后召回不得明显下降；
- 无垃圾录像经状态机确认后的持续误报：融合总量 **≤2 个/小时**，并分别报告 semantic、小垃圾模型和两路重合事件；
- 误报必须提供 contact sheet 并按来源、区域、目标尺寸分类；
- 8～11px 只报告挑战集召回，不阻塞首版；
- 不能用合成数据结果替代上述真实盲测结果。

如果真实正事件少于 20 个，召回率只作为探索数字，不做生产 Go。需要通过 shadow 模式继续积累。

为防止再次无限投入，训练前冻结中间停损规则：第一轮在真实 `≥12px` 事件上的召回若低于 20%，且正负候选分数没有可用排序，则直接 NO-GO；只要有明确、可补的数据缺口（召回不足或某一路困难负例过多），才允许 Phase 3 的唯一一次定向修正。第二轮必须同时达到最终召回和误报门槛，否则停止该模型版本。若现场正事件不足 20 个，这条规则延后到 shadow 收集完成后执行，不用合成命中率代替。

### 9.2 在线门槛

- 小垃圾分析旁路使用 latest-wins，队列容量 1；
- 不得降低主 RTSP pipeline / publish FPS 或造成画面冻结；
- 报告 GPU 显存、分析 tick P50/P95、帧年龄、丢弃 tick 数和主流 FPS；
- 先 shadow、不画框；再单路 canary；通过后才扩大摄像头范围。

## 10. 实施阶段与交付物

### Phase 0：冻结问题定义（0.5 天）

- 固定 camera、ROI、排除区、尺寸分层和事件标注规则；
- 冻结数据 manifest schema 与盲测隔离规则；
- 输出 30～50 个样本的标注示例集，由架构评审一次。

### Phase 1：数据工厂与审核（2～4 天机器运行，可断点续跑）

- 新增 `scripts/build_ground_litter_small_dataset.py`：按窗口拉 PS、抽帧、挖掘候选、写 manifest、删除 PS；
- 新增 `scripts/synthesize_ground_litter_small.py`：现场背景合成与精确标签；
- 复用或扩展人工审核页面，按事件 contact sheet 审核；
- 输出数据审计报告：日期/时段/目标种类/尺寸/分区/正负事件统计和泄漏检查。

### Phase 2：基线训练与冻结盲测（1～2 天）

- 训练 `yolo26s` 一类基线；
- 输出权重、配置、曲线、逐事件预测和失败 contact sheet；
- 在独立真实集上执行 Go/No-Go，不接生产。

### Phase 3：一次定向修正（1～2 天）

- 只针对 Phase 2 的主要漏检与高频困难负例补数据；
- 最多训练第二轮；
- 仍不达标则停止，不再通过阈值和状态机延时掩盖问题。

### Phase 4：旁路接入与 shadow（1～2 天开发 + 至少 24 小时观察）

- 新增 `rtsp_annotator/ground_litter_small_detector.py`，走 ROI tiles 和 batch inference；
- 接入现有 V3.3 event memory 与来源遥测；
- shadow 阶段不显示框、不影响现有输出，只记录候选与事件截图；
- 完成主流 FPS、帧年龄、显存和持续误报验收。

### Phase 5：单路 canary 与生产决策

- 先仅在目标摄像头开启；
- 明确回滚参数，保留现有生产镜像；
- 连续观察后再决定是否默认启用。

## 11. 本路线的第一个任务

先实施 Phase 0 和 Phase 1 的“数据可行性审计”，不要先改生产推理代码。必须回答：七天回放中有多少独立真实正事件、它们的原生尺寸分布是什么、困难负例有哪些、最终盲测能否保留。如果真实正事件不足，立即转入 shadow 数据采集计划，不把公共或合成样本冒充现场验收数据。

这一步的停损条件清楚：能够形成真实盲测集才进入模型验收；不能形成时只交付原型和采集工具，不再花时间修 Profile Factory。
