# 背景 Profile 先验路线 NO-GO 决策

日期：2026-09-21
状态：**生效，覆盖此前 Profile Factory 和自动 Profile Selector 的继续实施要求**

## 1. 决策

停止把 Clean Reference / Profile Bank 当成“通用小垃圾召回通道”。不恢复 v6，不继续建设原方案二的线上 Profile 自动选择与切换，也不把 v3、v4 或 v5 Bank 接入生产。

现有生产 V3.2、`turhancan_yolov8m_seg_trash.pt` 语义检测、V3.3 事件状态机和 `latest-wins` 旁路调度不因本决策自动删除或降级。后续路线改为：保留现有语义模型负责袋装垃圾、瓶罐和塑料袋；新增现场小垃圾检测模型负责纸片、小包装和零散垃圾；两路在事件层去重和确认。

下一路线见：[现场小垃圾检测模型路线](../plans/2026-09-21-ground-litter-small-detector-roadmap.md)。

## 2. 被否定的具体假设

本次否定的是：在当前摄像头、当前分辨率和现有 Clean Reference 算法下，即使给每一帧挑选最合适的 Profile，背景残差也能稳定召回 8～24 原生像素的多种小垃圾，并作为独立召回通道使用。

这不是“所有背景变化算法在任何条件下都不可能”的结论，也不否定 Profile 对环境匹配、画面漂移诊断或高对比大物体变化的辅助价值。只是这些窄用途不能满足当前业务目标，不能继续驱动生产架构。

## 3. 决定性证据

实验产物：`output/ground_litter_prior_go_no_go_20260921/`。实验分支：`experiment/ground-litter-prior-go-no-go`，提交 `d81f306`。

| 指标 | 结果 | 预注册门槛 | 含义 |
| --- | ---: | ---: | --- |
| v3 oracle 总命中率 | 98/768 = **0.1276** | GO ≥0.70；NO-GO <0.50 | 即使允许遍历全部 Profile，上界仍很低 |
| v3 12～24px oracle | 97/576 = **0.1684** | GO ≥0.70 | 排除最小 8px 后仍不足 |
| v3 16～24px oracle | 91/384 = **0.2370** | GO ≥0.70 | 业务可见尺寸仍不稳定 |
| 彩色包装、半透明模板 | **0 命中** | 应覆盖多类垃圾 | 不是单纯尺寸阈值问题 |
| paired baseline 歧义 | 0/1536 | 越低越好 | 命中统计没有被原图既有候选虚增 |
| 最终 prior 输出 | 0/768 | 输出命中率 GO ≥0.50 | 能力门禁与 Selector 还有损失，但不是首要失败原因 |

失败发生在 oracle 层。继续修剪枝、输入边界、Bank 能力字段、Selector 驻留时间或 Profile 切换逻辑，无法把 0.128 的信号上界修成可用检测器。

## 4. 证据边界

本实验只使用 4 个真实 PS 中的 12 帧，并在真实背景上合成注入目标；没有真实垃圾正样本。它证明的是“当前算法对这些结构信号没有足够召回能力”，不代表真实垃圾准确率测量。

负样本持续误报阶段没有完成，因此没有可信的 confirmed FP/hour。也没有覆盖完整夜间、强阴影和雨后环境。由于预注册规则允许 oracle 低于 0.50 单独触发 NO-GO，这些缺口不改变停止当前路线的决定；它们也不得被写成已经通过。

## 5. 停止与保留边界

停止：

- Profile Factory v6 的继续开发、测试和完整重建；
- 原方案二的生产 Bank 加载、在线自动切换和 Profile 生命周期接入；
- 将 v3、v4、v5 Bank 描述为可用小垃圾先验；
- 通过降低阈值或延长状态机确认时间掩盖 oracle 信号不足。

保留：

- 回放文件列表、PS 有界下载、Range 续传、即时处理与删除能力；
- ROI 几何、抽帧、按日期/文件/事件划分、防止数据泄漏的基础设施；
- V3.3 事件合并、遮挡、清走、再次投放和 `latest-wins` 调度；
- Profile 代码与实验产物作为历史证据，不进入默认生产配置。

## 6. v6 暂停现场的处理

v6 有 6 个已跟踪文件和 1 个计划文档的未提交草稿，尚未跑完新增回归，也没有 v6 Bank。保持原样，标记为暂停现场；不得把它合并、部署或描述为已验证。除非以后出现新的、预注册的背景变化用途和正向实验数据，否则不恢复。

## 7. 重新开启条件

只有出现与当前业务直接相关的新证据时才重开，例如在独立真实垃圾集上证明一种新的背景差分算法对 ≥12px 目标事件召回率达到 70%，并同时满足持续误报门槛。仅增加 Profile 数量、修复工程契约或更换同类采样方法不构成重开理由。
