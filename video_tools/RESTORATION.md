# 渔政录屏局部跨帧修复

2026-09-08，本地离线演示工具。原 `stabilize_fishing_demo.py` 保留；本工具不连接
摄像头/服务器、不上传录像、不调用生成式服务。船号 `粤清城渔10032` 是用户指定的
演示结果，不是本工具实际执行 OCR 后得到的结果。

## 处理方式

1. 从红/青/绿旧 OSD 中筛选长直线，单独补齐旧标签的文字孔洞；保护画面上方原有信息。
2. 按运动场对齐前后邻帧；同时检查前后向一致性、周围真实像素色差和邻帧 OSD 掩膜。
3. 只把可信邻帧纹理回填到掩膜像素；剩余位置用小半径局部修补。没有整船模糊、
   整幅降噪、降分辨率、生成式船牌重绘或超分辨率。
4. 每帧从对应原始解码画面开始。重复摄像头画面只复用修补小块，保留原帧内容和时序。
5. 独立船牌候选产生可编辑的密集关键帧，已按每两秒局部截图检查 30–60 秒段。
   船体轨迹以旧框范围为初始定位，经短时中值平滑和边缘留白整理；并非新检测模型。
6. 32 秒开始船号演示，33.2 秒显示预设文字；细青色整船框和金色船牌角框分开显示。

## 重现

在 rtsp 目录运行，使用本项目 Python 3.12 环境：

```sh
.venv/bin/python video_tools/restore_fishing_demo.py \
  '/Users/mlcbppg/Desktop/渔政资料/渔政录屏_裁剪.mov' \
  output/渔政录屏_局部跨帧修复_无损母版.mkv \
  --annotations video_tools/fishing_demo_keyframes.json --lossless

.venv/bin/python video_tools/export_fishing_delivery.py \
  '/Users/mlcbppg/Desktop/渔政资料/渔政录屏_裁剪.mov' \
  output/渔政录屏_局部跨帧修复_无损母版.mkv \
  output/渔政录屏_局部跨帧修复_演示版.mp4
```

采样：`--sample 20 30 40 50`，输出原尺寸修复图、演示图、掩膜与统计 JSON。
短片：`--start 38 --duration 5 --lossless`。导出器读取同名 `.audit.json`，逐帧
恢复原片 PTS，避免 Matroska 毫秒时间基对播放版时间戳的舍入。

`--prepare-annotations` 可以重新生成关键帧 JSON，但自动候选仍应视觉复核。
当前检测阈值、轨迹、中文字体、展示时间和布局只针对这段固定素材，不能直接用于其他录像。

## 画质边界与验证

- RGB 无损母版只保证相对于处理后 RGB 帧没有额外编码损失，不表示被红框遮住的原始
  场景已被无损恢复。被遮挡纹理是估计值，局部粗线、船篷边缘和水面标签处仍可能有修补痕迹。
- MP4 使用 H.264 CRF 10、BT.709、原始分辨率和原始 PTS，是有损的高质量兼容副本。
- 原片只有视频流，没有音频流；本次不需要音频复制。
- 38–43 秒样片共 300 帧；播放版与对应原片 PTS 的最大误差为 0 秒。
- 该样片平均 3.3316% 像素属于旧 OSD 修补掩膜，146 帧复用了静止源画面的修补小块。
- 第 40 秒未编辑水面 ROI（x=2600:3200, y=1400:1650）原片与母版 RGB 完全相同。
- 新增测试检查真实红色物体/蓝色船牌保护、掩膜外像素一致、空掩膜直通和轨迹失效边界。
- 4 项新增修补测试通过。全量 284 项首次运行有 3 项共享推理测试超时；单独预加载
  PyTorch（本次冷启动耗时 275.931 秒）后，4 项共享推理测试全部通过，未更改这些
  测试、其超时阈值或共享推理代码。记录位于 `output/quality_review/` 下对应日志。
- 5 秒初版样片的框颜色和卡片位置早于最终版；完整视频采用细青框和下移的卡片。

审计 JSON 记录每帧源 PTS、时间、掩膜像素数及空间/时间修补计数。它不能测量被遮挡区域
