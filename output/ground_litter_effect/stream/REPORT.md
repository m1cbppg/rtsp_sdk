## 结论一句话

这条流**永远显示不出垃圾框**，不是模型没看见，而是**区域多边形把模型看到的东西全部切在界外**：
模型 conf>=0.13 的 111 个候选，中心 111/111 都落在 5 个区域之外。

## 为什么全被拒

- 区域外（中心不在任何多边形内）：**111 / 111**。
- 区内候选（含低阈值 0.05）：51 个，但 **最高 conf 只有 0.127**，低于最低区域阈值 0.13；
  且多为 1600–18000px² 的大团块或 8–21px 的碎块。
- 所以：**区域级阈值 0.13/0.20/0.25/0.34/0.34 在这条流上一直是空转的**，
  `local_actor_max_crops: 3`（局部人车复检）也从未执行过——它排在 ROI+conf 门槛之后。

## 反事实验证（离线回放同一批 37 帧）

| 变体 | 有最终候选的帧 |
| --- | --- |
| 当前部署参数 | **0 / 37** |
| 区05 右边界外扩到 0.32/0.30，**其余全不变（阈值仍 0.34）** | **17 / 37** |
| 区05 外扩到 0.30/0.24 + 阈值 0.20 | 14 / 37（广框时中心仍出界） |
| 只降阈值（不动多边形）到 0.12 / 0.10 / 0.08+4/16 | 1 / 2 / 6 帧 |

**结论：改多边形有效，降阈值几乎无效。**
